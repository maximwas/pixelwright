Pixelwright docs

Quick start

Requires Node.js 24.11 or newer and Figma Desktop. Run the setup in a terminal:

npx -y pixelwright@latest setup

It connects Claude Code and Cursor, shows what to paste for Codex and other MCP clients, and puts the Figma plugin in ~/.pixelwright/plugin. Then, in Figma Desktop:

  1. Plugins → Development → Import plugin from manifest… and pick ~/.pixelwright/plugin/manifest.json, once. Figma loads the plugin from there every time you run it, and the setup puts the new one there on every update.
  2. Open your file and run Plugins → Development → Pixelwright. Keep its small window open while you work.
  3. The first time, the window asks for a pairing code: your agent shows it (from status); type it in.
  4. Select a section in Figma and ask your agent to build it.

npx -y pixelwright@latest setup --print asks nothing: it puts the plugin in place and prints the commands and config blocks, for scripts.

Try it on the demo

Open the Orbit demo in Figma: a small pricing site made for Pixelwright. Duplicate it to your drafts, run the plugin in your copy and ask your agent to read it: three breakpoints, an A/B hero, a prototype flow, Dev Mode notes and measurements, variables and styles, and components with variants, an exposed instance and a slot.

How it works

Claude Code ──stdio──► pixelwright ──ws://localhost:18720──► Pixelwright plugin ──Plugin API──► your Figma file

The plugin runs inside the file and answers the server on your computer. Every read goes through the Figma Plugin API, so nothing reaches api.figma.com and no seat or plan limits the number of calls. Several files can be connected at once; tools work on the one whose plugin window was in front last, or on the file you name.

Safety

  • No REST API, no token. The plugin reads the file through Figma's Plugin API, on your computer. The server listens on localhost only, and a plugin pairs once with a code you type in; unpaired windows get nothing.
  • This version reads. Every tool reads, except execute, which runs plugin code the agent writes (or a script over the reads, which never writes), to read what no tool shows. Allow edits in the plugin window is off until you turn it on for a file; while it is off, the plugin refuses every write that code tries. Your choice is remembered per file on your computer. Ask for an edit, and your agent warns that editing is not supported in this version and goes on only when you say so.
  • execute runs code the agent writes: use Pixelwright with agents you trust, as you would with their build scripts.
  • What is stored where. ~/.pixelwright/ holds the plugin, the bridge's state (bridge.json), the shared log in logs/, npm's newest version (latest.json), the asset files written (written-files.json) and the library catalogues library_search saved (libraries/). Baselines go into the project's .pixelwright/baselines/. The plugin keeps its pairing key and your Allow edits choice in Figma's storage on your computer.
  • What goes online. The server asks npm for the newest version once a day, and fonts_check asks Fontsource and Google Fonts which fonts they serve. The plugin's only network access is the server on localhost.

Limits

  • The file must be open in Figma Desktop with the plugin's window open. Figma slows plugins in background tabs: keep the file's tab in front during a long read.
  • This version reads only. The tools that write to the file, and the design checks, come back in 0.9.0 and 0.10.0.
  • Tested on macOS. On Windows the setup gives Claude Code cmd /c npx …, as its documentation asks; Windows itself is not tested yet.

Commands

pixelwright                 in a terminal: the setup; started by an MCP client: the MCP server on stdio
pixelwright setup           the setup: connects your MCP clients and puts the Figma plugin in place
pixelwright setup --print   no questions: the plugin put in place, the commands and config blocks printed
pixelwright serve           the MCP server, however it is started
pixelwright logs            follow the logs of every running server on this machine: tool calls, plugins, errors
pixelwright --version

PIXELWRIGHT_HOME moves ~/.pixelwright; CLAUDE_PROJECT_DIR names the project (baselines, and relative paths when the client gives no root); PIXELWRIGHT_PLUGIN_BRIDGE=off starts the server without the bridge; PIXELWRIGHT_NO_UPDATE_CHECK=1 stops asking npm for a newer version (see Updating); PIXELWRIGHT_LOG_LEVEL=debug adds the bridge's details to the log.

Updating

MCP clients start pixelwright@latest, so a client started again runs the newest server. The plugin is a copy on your computer: run npx -y pixelwright@latest setup again (or setup --print) to put the matching one in ~/.pixelwright/plugin. Figma Desktop loads it the next time you run the plugin. When the plugin's window says the protocol versions differ, this is the fix.

When a newer version is out, the plugin's window says so at the top. Close it, and it stays closed until the next version. The server asks npm for the newest version once a day (the answer kept in ~/.pixelwright/latest.json); PIXELWRIGHT_NO_UPDATE_CHECK=1 turns that off.

Every MCP client session runs its own server. The first one holds the bridge port and the others work through it, so every client sees every connected file. A newer server takes the bridge over; the older one then asks you to restart Pixelwright in its client (/mcp in Claude Code).

From 0.7.0 to 0.8.0

  • Put the new plugin in place. Run npx -y pixelwright@latest setup and run the plugin again: a 0.7.0 plugin cannot connect to 0.8.0, whose protocol changed. The plugin's path is the same, so you import nothing again.
  • Restart Pixelwright in every MCP client still open (/mcp in Claude Code): a 0.7.0 server that keeps running keeps 0.7.0's answers.
  • 0.8.0 reads. The tools that wrote to the file, and the design checks, are gone until 0.9.0 and 0.10.0; execute stays, to read. Code Connect is gone too: the XML no longer carries your project's code for an instance.
  • An argument a tool does not name is an error now, which names it; 0.7.0 ignored it.
  • Baselines 0.7.0 saved still read: baseline_diff compares against them as they are.

Tools

Every tool the server registers, as your agent sees it. A tool marked can write changes the file only while Allow edits is on in the plugin's window.

assets_export Export assets

Writes files out of the design into dir. nodes: up to 50 layers, one file each (SVG for an icon, PNG at 2x otherwise, or the format and scale given; PDF too; WEBP keeps transparency exactly at any quality, which sets how lossy its colours are, 85 by default). from: every true asset inside one layer, the icons and images design_read would plan. original: the images as they were placed instead of renders (photos at full size, in their own format). Files are named after their layer (Rectangle 61: rectangle-61.png), or as names gives a layer id. The same bytes are written once, a name taken by other bytes gets -2, and a file already in dir is never overwritten with other bytes. A layer that cannot be exported is reported in errors and the rest are still written.

baseline_diff What changed since a baseline

What the designer changed since baseline_save, in design_read's terms: each layer changed (its attributes as [before, after], a text's content as XML), added (with its XML when short), removed or hidden, moved to another parent or reordered; a change made in a component once, with the instances it reached and how many were compared (of); tokens whose value changed in any mode, renamed, newly used or no longer used; icons and images drawn anew (drawing: export them again). Layers are followed by id, a replaced one by its name. It sees what changes_since and Figma's own Changed mark miss: edits made while the plugin was closed, accepted library updates, variable and style values. Without name: every baseline in the project with how much changed; call it when a session starts or the user says the design changed. It reads the file the baseline came from and works while Allow edits is off. Change only the code it names (code lists the files), then call baseline_save with the accept it gives.

ParameterTypeWhat it is
nameoptionalstringOne baseline in detail. Without it: every baseline in the project, with how much changed.
nodeoptionalstringCompare with this layer instead of the baseline's own, e.g. a v2 the designer made beside it. Needs name.
fileoptionalstringWith name: compare in this file (a session from status, or a file name). Without name: only this file's baselines. Default: the file each baseline came from.

baseline_save Keep a baseline

Keeps a layer as you build code from it, so baseline_diff can tell later what the designer changed: its read and the values of the tokens it uses, in every mode, go into .pixelwright/baselines/<name>.json in the project (it holds the design's texts: commit the folder to share it, or leave it out of git). Save right after the design_read you build a screen or section from; name it after your code (pricing, plan-card) and list in code the files you build from it. Once your code has the changes a baseline_diff listed, pass the accept it gave: exactly the design it compared is kept, so what the designer changed after it still shows next time. An existing name is replaced only with accept or replace: true; code alone changes its file list. Writes nothing to Figma, so it works while Allow edits is off.

ParameterTypeWhat it is

nameoptionalstringNamed after the code: pricing, plan-card. Default: the layer's name as a slug. Required with accept.
codeoptionalstring[]The project's files built from the layer, relative to the project. Default: the list the baseline already has.
acceptoptionalstringThe accept a baseline_diff answer gave: keeps exactly the design that diff compared.
replaceoptionalboolean
default false		Start the named baseline over from the layer as it is now. Not with accept.
fileoptionalstringThe file to work on: its session from status or its name. Default: the active file.

changes_since What changed

What changed in the file since the plugin started watching (its window opened) or since an earlier answer's cursor: each layer created, deleted or changed (with the properties), by the user, a collaborator or Pixelwright itself, on the page the user was on. components_read Read the components

design_read Read a design

Reads a layer (a section, a card, a screen) as Pixelwright's XML: Figma's layer types as tags, ids to name a layer in the other tools; a hidden layer is a stub with display="none". The first text block is the XML; the second is JSON with node (the layer read), tokens, textStyles, fonts, assets, measurements (the designer's Dev Mode measurements, when there are any), hints (what the code should know or fix, one per kind with a count and examples) and truncated (ids of layers the read cut: $children="N" where not all children were read, $truncated="true" where a branch or a text was cut to fit maxChars: read each on its own); with repeats, runs of three or more alike neighbours read as their first with $repeat="N", and JSON repeats holds each one's own values as rows; with nearby, JSON nearby lists the designer's notes around the screen. For a big frame, find its sections with outline first; guide xml explains every tag and attribute.

execute Run plugin code can write

Runs JavaScript to read the file, given one of three: code, Plugin API code run in the Pixelwright plugin, for what the read tools do not show; codePath, the path of a file of such code; script, code run on the server where pw.<read>(args) calls a read tool by its camelCase name with its own arguments (pw.nodesFind, pw.inspect, pw.designRead; not screenshot, node_show or selection_wait: a script cannot show an image or act on the user's view, so call screenshot yourself) and utils helps filter and join their answers, for one answer that needs several reads filtered or joined: a script never writes, and reading a key its answer type lacks throws (types_read gives each read's answer type before you write a script; guide script has the limits and utils). Plugin code is the body of an async function given figma (the Plugin API, without clientStorage, ui, closePlugin and showUI), console and pw; return gives result (layers come back as {id, type, name}, figma.mixed as "mixed"), and what it logs comes back as logs. What it throws comes back as error, with the logs before it. pw stays between calls while the plugin window is open: pw.state for your data, your own functions added to pw, and Pixelwright's helpers: await pw.node(id) (the layer, or an error), await pw.fonts(layer) (loads every font its texts use, before you change them). The plugin runs with documentAccess "dynamic-page": use the Async calls (getNodeByIdAsync, getMainComponentAsync, getLocalPaintStylesAsync, setFillStyleIdAsync…), and await page.loadAsync() before reading another page. figma.skipInvisibleInstanceChildren is Figma's own, false in the editor and true in Dev Mode: set to true, findAll, findOne and children skip hidden layers inside instances and getNodeByIdAsync gives null for them (it is set back after the call). Keep long plugin code in a file and pass its path as codePath: it is read at every call, so after a plugin restart or a change to the file run it again rather than calling the functions it once added to pw. What it changes during the call is one undo step in Figma. Refused while the plugin's Allow edits switch is off, but code it starts that outlives the call (timers, listeners, work past the timeout) keeps running until the plugin window is closed, the switch notwithstanding. timeout waits up to 300 s for a long task; an endless loop, synchronous or of awaits, freezes Figma until the plugin is closed. This version reads only: if the user explicitly asks to change the file, warn that editing is not supported or stable in this version, and write only once the user says to go on; the Allow edits switch still gates every write. The reads answer what code is most often written for: layers by text (a list, or textRegex), size, visibility, component and the properties instances change, with their ancestors and page (nodes_find, outline, file_map, components_read); a whole subtree with its auto layout gaps and paddings, parent layout, text runs and component properties (inspect within and fields); a token by name with its id and alias chain (tokens_read query); colours bound to no token (tokens_usage raw: true). Before code, try the read tools (design_read, inspect, measure, nodes_find): they need no code and work with Allow edits off, and their answers come from the same Plugin API, so do not re-check a read's answer with code (an absent field is its default, as each read's description says); code in which nothing writes (no property set, no create*, remove, set*… call, no helper of your own) is told so in note.

codePathoptionalstringA file of such code on the server's disk, run instead of code. It is read at every call, so the file as it is now runs, after a plugin restart too. inspect Inspect layers

Reads layers as Figma has them, for what design_read's CSS cannot say, without running code (works while Allow edits is off). Recipes: fills, strokes and bound variables of every layer under a card: within + fields ["fills","strokes","bound"]; a layer's and its parent's auto layout (padding, gap, direction): fields ["layout"] gives layout and parentLayout; a mixed text's runs: fields ["text"] gives segments; how far a layer overflows its parent, and its boxes: fields ["box"]; its ancestors by id and its page: fields ["path"]. An absent field is at its default (no padding-* keys is padding 0: with any side set, all four are listed, 0 included; no gap key means no gap shown, which includes a spread layout, one visible child or a negative gap; no flex-direction is row; no overflow is none, absolute-positioned layers excepted) and the answer is complete unless more is true or a note says the scan stopped. inspect does not say whether a layer is hidden: use nodes_find with visible: false. Also: the layout box and the painted box (centred or outside strokes, shadows and blur reach past it), the blend mode of the layer and of each fill, the fill as a CSS value with the paint style or variables behind it and every fill's type, the variables bound to its padding, gap, radius and size, how strokes paint (align, per-side weights, dashes, the variables their colours are bound to), every effect with Figma's own parameters, a text's lines with what ended each (Enter or Shift+Enter) and its line heights, its prototype interactions, its component's variant and every component property with its value and the component's default. within reads a whole subtree in one call (depth levels); nested instance ids such as I54:244;54:205;54:188 work as nodes. Boxes and each layer's centre are measured from relativeTo's top left, so it also measures: give a list of layers and their section. For layers set around a circle, around (the circle's id, or a point) adds each centre's distance from it and its angle as CSS rotate() turns (0 up, clockwise). Up to 100 layers a call: left counts the selected layers past them, more and leftIds a subtree's.

Guide: workflow

Which tool to use when, from finding a section to its files, and how to read a design like a web developer. The agent reads this with guide topic workflow.

Pixelwright reads the files open in Figma Desktop through its plugin; nothing goes through Figma's REST API. This version reads only: no tool changes the file. Every tool that reads a file takes file (a session id from status, or a file name); without it, the active file, except baseline_diff, which compares a baseline in the file it was saved from.

  1. Connection. status lists the connected files and which one is active. None connected: the user runs the Pixelwright plugin in Figma Desktop and keeps its window open (the first time, they type the pairing code status shows into the plugin window; never type or send it yourself).
  2. Find what to read.
    • file_map: every page with its frames, sections and components, in one call: where to start in a big file.
    • selection_get: what the user selected ("this", "the selected one"). selection_wait: ask the user to select something, then wait for it. viewport_get: what the user is looking at, when "this" comes with no selection.
    • outline: the layer tree with boxes, x and y relative to the outlined layer; node: "0:0" lists the pages. A layer with $children="N" has more children than listed: outline it on its own. An instance names its component and variant, so repeated cards show without a read; dev marks what the designer handed over for development: build those first, not drafts.
    • nodes_find: layers by name, type, text, component or an instance's variant ("State=Hover, Size=L"), on the current page, inside a layer or across the file (within: "file"). counts: true counts every instance found by component and variant: which variants the layers use. Each layer says hidden when a viewer does not see it (visible: true or false keeps only shown or hidden ones), a text its fontSize, an instance the properties it changed from its component's defaults.
    • node_show: brings layers into view and selects them, so the user sees which you mean.
    • changes_since: what the designer changed since you last looked (a cursor), to read again only that.
  3. Read one section. design_read returns the section as XML (guide xml explains every tag and attribute), then JSON with tokens, text styles, fonts, assets, hints and truncated, plus measurements (the designer's Dev Mode measurements, in px) when the section has them. Read sections, not whole pages: past maxChars (80 000) the deepest branches are left empty with $truncated="true" and their ids listed in truncated; read each on its own. Pass assetsDir (e.g. src/assets) to get its icons and images written as files (guide assets). repeats: true reads a list of alike items once ($repeat), with their data as rows: shorter, and the list's shape plain. nearby: 400 adds the designer's notes on the canvas around the screen (texts and stickies beside it, nearest first): read them, they often say what the layers cannot (states, motion, copy to change).
  4. Look at it. screenshot renders a layer to PNG (inline up to 2000 px a side, scaled down to fit; save writes a .png file full size; clip takes a region of it, in px from its box). Compare your build with it: image_compare renders a layer the same way and compares it with a PNG of your build, or with another layer (against): rmse, the share of pixels that differ, the box around them, edges off by N px; diff writes the difference as a PNG. styles_compare checks the build's computed styles (getComputedStyle) against each layer, property by property: the values that differ with the token or text style behind them, and the properties the build left out. Measure it. inspect reads layers as Figma has them, without code: the layout box and the painted box (a centred stroke, shadows and blur reach past it), the blend mode of the layer and of each fill, the fill with the style or variables behind it (what a var() resolves to) and every fill's type (a video's too), how strokes paint and the variables their colours are bound to, a frame's auto layout as layout (design_read's CSS longhands in px: padding-top, gap, row-gap), every effect's parameters (a progressive blur's start and end), a text's lines and line heights, overflow, interactions with their transitions, a component's variant and properties with their defaults, and each layer's centre. Items set around a circle (a round menu, labels on a dial): around (the circle's id, or a point) gives each centre's distance from it and its angle as CSS rotate() turns, 0 at the top, clockwise. measure gives the distances between layers, each from the one before (gaps, aligned edges, insets). Compare. nodes_diff says how one layer differs from another (A/B screens, a card and its copy): the layers only one has, the attributes that differ, and icons whose drawing differs. variants_read gives a component's states as differences from its default (build :hover, :active, :disabled from them). breakpoints_find finds a screen at the page's other widths, for the media queries. flow_read maps the prototype: screens and the links between them.
  5. The design system. tokens_read: variables with every mode (light, dark…) and styles, as CSS, JSON or DTCG token files (guide tokens); query keeps the ones whose name has that text, each variable carries its id. tokens_usage: the layers a token is used on; with raw: true, the colours bound to no style or variable, each with the layers using it. components_read: the components a page uses, or the file defines, with variants and properties. library_search: components of the team's libraries, saved once from each library file. fonts_check: the fonts used and where the build gets each (Google Fonts links).
  6. Files. assets_export: several layers, or every asset inside one, as PNG, JPG, WebP, SVG or PDF, or the images as they were placed (original: true); width sizes a render by the CSS width the build shows it at (110 at scale 2: 220 px). When a file gets another name than design_read planned (planned), use the path it gives.

Right after the design_read you build a screen or section from, baseline_save {node, name, code} keeps it in the project (.pixelwright/baselines/: commit it to share, or leave it out of git, since it holds the design's texts). Reading a design like a web developer

A design shows the look, not the build. design_read's hints say where the two part; read them before you write code.

  1. Workarounds. Children placed absolutely inside an auto layout parent, empty layers that only make space, and texts broken into lines by hand are often how the design tool got the look: build a flow with that gap, use the parent's gap or padding, and let the text wrap in its width.
  2. Gaps and components. Children spaced evenly in a frame without auto layout are a flex or grid with that gap. A structure built three times or more without a component (cards, rows, tabs) is one component with instances (repeats: true reads them once, their data as rows).
  3. Fixed sizes. A text or content frame of fixed width narrower than its column fills it with a max-width; a frame of fixed height that clips its content grows with it, unless the build means to cut it.
  4. Baked fades. A fade baked into an image (a gradient over a photo, often at a section's edge) stretches with the box once exported flat: export the raw image (assets_export with original: true) and build the gradient in CSS (guide assets).
  5. Tiled textures. A frame filled with a tiled texture renders coarser or finer at another scale: the hint gives the scale; export one tile at it and repeat it.
  6. Blend modes and video. They change the look completely: inspect gives the layer's and each fill's blend mode and each fill's type; design_read writes mix-blend-mode, and lists a video fill as an asset no file holds (guide assets).
  7. States. Top-level frames of one size that share most of their layers (a section and its copy with another tab active) are states of one component: build it once, with variants; nodes_diff lists what differs.
  8. Missing fonts. A text whose font is not installed here was laid out with a fallback, and the hints name it: its spacing may differ only for that reason, so do not "fix" it. fonts_check says where the build gets each font.

Build the code from the XML with the project's own components, tokens and layout conventions: the XML is the spec, not the code to paste. Hints in design_read also say what Figma left unbound (raw colours equal to tokens, raw spacing, radii and strokes Figma itself matches to a token, unnamed layers, frames without auto layout) and what instances changed outside their component's properties.

  • A hidden layer is a stub with display="none": its id and name (and $visibleProp when a component property shows it), no box and no children. Slices are left out.

Metadata attributes, in this order

id (instance children keep I…;… ids), name (left out on a text named by its content), component and variant ("Size=Large, State=Default") on instances, props (an instance's text and boolean properties, "Label=Sign up, Icon=true"; a comma, = or backslash inside a name or value comes escaped with a backslash), $exposed, description (components), note (Dev Mode annotations, "Category: text", several joined with " | "), $pins, $override, $dev, $locked (see Read-only attributes), href (a prototype link, or a text's hyperlink), target (_blank when the prototype link opens in a new tab), data-<collection> (a variable mode set on the layer, data-color-modes="dark"; the read's root also has the modes it takes from above), textStyle, mask (alpha, vector or luminance: the layer masks the layers above it in its parent), src (assets), d and start (a text on a path). The CSS attributes come next, then $prop, $visibleProp, $swapProp, $css, $grid-style and $on-…, and last $children, $truncated and $repeat.

A data-<collection>="<mode>" attribute is the selector tokens_read's CSS writes for that mode: put it on the element in the build too, and the element takes that mode's values.

CSS attributes

Ready CSS values, in this order: display, flex-direction, flex-wrap, position, left, right, top, bottom, width, height, min/max sizes, flex, align-self, grid-row, grid-column, justify-self, padding, justify-content, align-items, align-content, gap, column-gap, row-gap, grid-template-columns/rows, transform, opacity, mix-blend-mode, overflow, text-overflow, white-space, border-radius, border (or border-top…, outline), background, box-shadow, text-shadow, filter, backdrop-filter, font, letter-spacing, text-transform, text-decoration (with text-underline-offset, text-decoration-thickness), text-align, text-wrap, color.

  • Sizes: fixed sizes in px; hug writes nothing; fill is flex: 1 along the parent's direction and align-self: stretch across it. The layer you read always has its width and height.
  • A turned layer has transform: rotate() and is placed by its centre; a mirrored one scaleX(-1).
  • Colours bound to a style or variable are var(--Name), a shadow's colour too (see guide tokens); the values behind them are in the JSON tokens. In a Display P3 file every colour is color(display-p3 r g b) (as tokens_read writes it too): keep it so, it is what the designer chose. A text with a textStyle carries only what differs from the style; textStyles holds the style's font.
  • Lengths are whole pixels; stroke widths and blurs keep two decimals, and letter spacing keeps its fractions.
  • filter: blur() and backdrop-filter: blur() are 0.43 of Figma's blur radius: Figma renders a radius R as a Gaussian of about 0.43 R (measured on layer and background blurs of radius 4 to 40 against Chrome), so radius 20 is blur(8.6px), and a blur(v) here is Figma's radius v / 0.43. Dev Mode writes radius / 2, which is softer.

Values

  • Lengths are px (0 stays bare); a token where the designer bound one (gap="var(--space-16)").
  • font is the shorthand [italic] weight size/line-height 'Family': font="italic 500 14px/20px 'Inter'", the line height in px, or normal for Figma's Auto (see Text).
  • background holds colours and gradients, the top paint first as CSS stacks them: linear-gradient(<angle>, <stops>), radial-gradient(<rx> <ry> at <x> <y>, <stops>) and conic-gradient(from <angle> at <x> <y>, <stops>), a stop a colour or a token and its place in percent. A diamond gradient, a turned radial one and repeating gradients are in $css, as Figma's own CSS.
  • mix-blend-mode is how the layer blends (multiply, screen, overlay…); a blend mode CSS has no name for is in $css.
  • background-blend-mode follows background when a fill blends with the fills under it: one mode per background, top first (multiply, normal). A mode it has no name for (linear burn or dodge) is in $css, and so is a text's (fill-blend-mode: color cannot blend).
  • A text's stroke follows color as -webkit-text-stroke="2px #3B2FD9", which CSS centres on the glyph's edge: an outside stroke is twice as wide with paint-order="stroke fill", so the fill hides its inner half; an inside one has no CSS and is in $css as stroke-align: inside.
  • text-decoration is on a Text only when every run has it: CSS draws a parent's underline through every child, so otherwise each underlined or struck-through Span carries its own.
  • A drop shadow Figma shows behind a see-through layer is filter="drop-shadow(0 4px 6px #000)", before the layer's blur(): CSS cuts a box-shadow out under the box, while drop-shadow() draws under the layer's see-through pixels, following their alpha (children too). Its blur is a standard deviation, half a box-shadow's blur radius, so it is half Figma's radius. One with a spread, which drop-shadow() has not, stays a box-shadow with shadow-behind in $css.
  • mask="alpha" (or vector, luminance) makes the layer the mask of the layers above it in its parent.

Layout as the XML shows it

  • Flex. Auto layout is display="flex": a row, or flex-direction="column", flex-wrap="wrap" when it wraps; defaults are left out (row, flex-start, gap 0), and a gap is written only between two or more children. justify-content aligns along the direction (flex-start, center, flex-end, space-between), align-items across it (flex-start, center, flex-end, baseline). Figma aligns all children alike, so a child's align-self is only ever stretch.
  • Grid. Grid auto layout is display="grid" with grid-template-columns and grid-template-rows, each a list of tracks: 200px is fixed, 1fr takes a share of the room left, auto fits its content; three or more equal tracks are repeat(3, 1fr). row-gap and column-gap space them. Each child has its grid-row and grid-column, lines counted from 1 as in CSS, with span when it spans (grid-column="1 / span 2"); a cell holds one child. In its cell a child sits where justify-self (horizontally) and align-self (vertically) put it: start, center, end, or stretch when it fills the cell. A grid has no justify-content or align-items: each child aligns in its cell.
  • Absolute. A child of a frame without auto layout, a section's child, and a child taken out of an auto layout flow have position: absolute and are placed against their parent element: give that parent position: relative in the build. Their edges follow the constraints: left/top when pinned to the start, right/bottom when pinned to the end, left and right without a width when stretched, calc(50% - Npx) when centred (left="calc(50% - 24px)" centres a layer 48 px wide, half its size), and percents when scaled with the parent. Later in the XML is drawn on top (there is no z-index).

Read-only attributes (start with $)

  • $css: what the CSS attributes cannot say, as Figma's own CSS: a diamond gradient, a turned radial one, blend modes CSS has no name for, a video fill, line clamps, lists, a negative gap ("children overlap"). It holds property: value pairs only, explained in hints: blur: progressive from 0px at 50% 0% to 8.6px at 50% 100% (a blur that changes across the layer; filter holds its end radius), stroke-align: center (half of the stroke paints outside the box, which a border-box border does not; inspect gives the painted box), list-spacing: 8px (the space between a list's items, apart from paragraph spacing), stroke-linecap: round (a line's round or square ends, which a CSS border does not draw), corner-smoothing: 60% (Figma's smoothing runs the corner's curve on past the radius into the edges; CSS's corner-shape keeps it inside the radius and has no match, so border-radius is the nearest) and shadow-behind: 0 4px 12px 2px #000 (a box-shadow Figma also shows through the layer's see-through fill, which CSS cuts out under the box: draw it on an element behind).
  • $children="N": the layer has N children and not all are listed (depth, or maxChars).
  • $truncated="true": the branch was emptied, or the text shortened, to fit maxChars; its id is in truncated.
  • $repeat="N": with repeats: true, the first of N alike neighbours (list items, cards, rows) stands for all of them; the JSON's repeats lists the run's layers and, a row per layer, the values they hold apart (texts, src, variant, props, href, position). Build one component and map the rows over it.
  • $exposed="true": a nested instance its component exposes: its properties are the component's API too.
  • $visibleProp="Show subtitle", $prop="Title", $swapProp="Icon": a component's layer bound to its properties: the boolean one that shows it, the text one its characters show, the instance swap one it is. In code they are the component's props.
  • $override="text, background": what this layer of an instance changes that its component's properties do not say (a feature text rewritten, an icon recoloured). Code built from the component cannot show it: give the component a property or a variant for it, or build that instance as a one-off. A hint lists them all.
  • $locked="true": the layer is locked on Figma's canvas. Nothing to build; it is said so an agent leaves it be.
  • $dev="ready for dev" on the read's root: the designer marked it (or a frame or section around it) ready for development (or completed).
  • $grid-style="Desktop 12": the grid style the frame's layout grid comes from.
  • $pins="width, padding": the properties the designer pinned in the layer's Dev Mode annotations, in CSS words: take those values exactly.
  • $on-click, $on-hover, $on-press, $on-drag, $on-mouse-enter, $on-mouse-leave, $on-mouse-down, $on-mouse-up, $on-key, $after-timeout, $on-media-hit, $on-media-end (any other trigger as $on-<trigger>): the layer's prototype interactions, e.g. $on-hover="change to Type=Hover; smart animate 300ms ease-out" (a variant to switch to on hover, and how: build it as the hover state); the easing is valid CSS, and a spring, which has no CSS, is named by its Figma type (200ms gentle). A link stays href, with target="_blank" when it opens in a new tab.

Text

  • &#10; is a paragraph break (Enter), &#8232; a line break inside a paragraph (Shift+Enter, <br> in HTML): never spaces.
  • line-height: normal is Figma's Auto line height, the font's own spacing (about 1.2× the size for most fonts). Where the build must match, read with autoLineHeight: "px": it writes the px Figma renders where the read can tell (a text that hugs its lines shows it for its font and size), and normal elsewhere.
  • A TextPath is a text set along a path. Its characters, spans and text CSS are a Text's (it has no line height, decoration, wrapping or truncation of its own); d is the path in the layer's own box, which left and top place as for any layer, and start where the text begins on it: the path's segment (from 0) and the place along that segment (0 to 1). text-align is anchored there: center centres the text on start, right ends it there. In code an SVG <textPath> over a <path d="…"> draws it:

Guide: tokens

How tokens are named and read: styles, variables, modes, aliases, units, libraries. The agent reads this with guide topic tokens.

design_read writes a bound colour or length as var(--Name) and lists the values it used in tokens; tokens_read returns the whole set, and tokens_usage the layers that use one.

Names

  • A style: its name with every run of other characters than letters, digits, _ and - turned into "-": "Dark" → --Dark, "Brand/Primary 500" → --Brand-Primary-500. Letters of any script stay.
  • A variable: its Web code syntax when the designer set one (var(--surface) → --surface), else its name the same way ("space/4" → --space-4).
  • A text style is --<name>-font, holding its font shorthand: font: var(--h3-font). Its letter spacing and case, when they are not the default, are --<name>-letter-spacing and --<name>-text-transform; an effect style's blurs are --<name>-filter and --<name>-backdrop-filter beside its shadows.
  • Two styles of one kind with one name (two paint styles "Black") are different tokens: the file's first keeps --Black, the next are --Black-2, --Black-3 (tokens_read notes them with their values). Use the one the layer names. The file's own styles come first; library styles are numbered among those the page uses, so every tool means one style by a name on that page (a read from another page may number a library's Black differently). Text styles are numbered alike: the second "h1" is --h1-2-font and textStyle="h1-2".

tokens_read

  • It takes the file's own styles and variables, and with used those the current page (or within) uses, a team library's among them: a file built on a library has its tokens there.
  • format css (default): :root holds every collection's default mode and the styles; every mode of a collection with several is a block [data-<collection>="<mode>"] with that collection's variables, the default's too (an element in it takes the default back inside another mode's). Put the attribute where design_read writes it (data-brand="dark" on a section) or on the html element for the whole page: a token in :root that points at another collection's token is computed in :root and does not follow a mode set lower in the page.
  • format json: per collection, its modes and each variable's value in every mode, with its scopes (when not every field) and its code syntax.
  • format dtcg: Design Tokens Format (DTCG 2025.10) trees, one per mode of each collection, keyed <collection>.<mode> (the collection alone when it has one mode), and one of styles, each to save as its own .json file for Style Dictionary or other DTCG tools. Aliases are {path}; a token whose path is also a group sits at the group's $root; a token takes the type of the tokens it is aliased with (a number a gap points at is a dimension), and one whose alias target took another type is written resolved, with a note. Named in notes: an alias to a token no tree here holds (a library's, a collection left out), a name taken twice (the second suffixed -2), what DTCG has no type or field for (a text variable, a boolean, an image style, a gradient's angle, a text style's case).
  • collections keeps only the named ones; libraries: true adds the enabled libraries' variables by name and type.
  • Past maxChars (80 000) the summary comes back with the first whole tokens that fit, and the collections to read one at a time.
  • An alias to a token the output leaves out (a collection you did not ask for) is named in notes.

tokens_usage

tokens_usage {token} lists the layers on the current page (or inside within, or on every page with within: "file") that use a style or variable, named by its token as above (--White-2, --h1-font, --h1-letter-spacing), with where each uses it (fill, stroke, effect, text, a text run, or a bound field). Use it to tell same-named styles apart, or to see what a change to a token would touch.

Values

  • Colours as hex (rgba when see-through); a colour with an opacity variable as color-mix(in srgb, … N%, transparent).
  • Numbers in px, except opacity and font weight, which have no unit.
  • Strings quoted; booleans as true or false (CSS has no booleans: a note says so).
  • An alias is var(--other). One that points nowhere is a comment and a note.
  • A gradient paint style is a token as linear-, radial- or conic-gradient().

Not tokens yet

Paint styles CSS cannot draw (an image, a diamond or a turned radial gradient, one without stops), effect styles with no shadow or blur CSS can write, and library variables the file does not use (Figma gives their values only once they are imported into the file: libraries: true lists them by name and type). The styles left out are named in notes; a var() design_read writes without a value is named in its hints.

Guide: assets

What becomes a file, in which format, how files are named, and what no file holds (a video). The agent reads this with guide topic assets.

Only true assets become files; everything else is CSS.

What is an asset

  • Icon (SVG): a vector, Figma Draw's transform group, or a group, frame or instance without auto layout drawn only with vector shapes, at least one of them a true vector (a logo, an arrow in a circle). Exported with everything it draws, strokes outside its box included, and sized by that box.
  • Image (PNG at 2x): a layer filled with an image, a mask group (its bottom layer is the mask), a layer with a pattern or shader fill or a noise, texture or glass effect. Exported as its own box: its corners, drop shadows and outline stay CSS around it, and the rest of its look (opacity, blur, inner shadows) is left to the file, as Figma renders it.
  • A layer the designer marked for export (PNG, JPG or SVG; a PDF export is not a web asset), in that format, when it holds no text (an export on a section with text is a preview, read as layers). A frame with an image fill and children keeps its children: the image is its background, written as the original image.
  • Plain rectangles, ellipses, buttons, cards, shadows are CSS, never images.

Video

A layer filled with a video is no file: the Plugin API exports none. design_read lists it in assets with kind: "video" and no src, its $css says the fill is a video, inspect gives the fill's type VIDEO, and assets_export reports it in errors with kind: "video" while it writes the rest. The build brings its own video file: ask the user for it, and use a render of the layer (screenshot) only as its poster.

Fades and textures baked into images

  • A fade baked into an image (a gradient fill on the photo's layer, or a gradient layer over a photo at a section's edge; design_read's hints name them) is flattened by an export and stretches with the box on wide screens. Export the raw image with assets_export and original: true, and build the gradient in CSS over it.
  • A frame filled with a tiled texture (a noise image repeated at a scale) renders coarser or finer at another scale: the hint gives the scale. Export one tile at that scale and repeat it in CSS, or replace it.

design_read vs assets_export

  • design_read with assetsDir writes the assets of the section it reads, and its XML points at the files.
  • assets_export writes files on their own: nodes (up to 50 layers, one file each, in the format and scale you give: PNG, JPG, WebP, SVG or PDF; width, the CSS width the build shows a layer at, sets the render to width × scale px) or from (every asset inside one layer). original: true writes the images as they were placed, full size and in their own format, instead of renders.
  • WebP keeps transparency exactly: its alpha is stored without loss at any quality. quality (1 to 100, 85 by default) is how lossy its colours are, so a transparent PNG becomes a WebP with the same see-through pixels.
  • design_read without assetsDir only plans names. When assets_export writes a file under another name (the name holds other bytes, the same bytes are another layer's file, an original is a JPEG), the file has planned: use its path in the src.

Files

Named after the layer (Hero photo → hero-photo.png, a component's variant added: brand-logo-dark.svg), or, in assets_export, as names gives a layer id ({"54:12": "hero-mountains"} → hero-mountains.png, slugged the same way). The same bytes are written once and shared; a name already taken by other bytes gets -2; a file already in the folder is never overwritten with other bytes.

Guide: script

An execute script over the reads: its limits, its utils, images and the answer types it reads by. The agent reads this with guide topic script.

execute with script runs JavaScript on the server, where every read tool is an async function on pw: one call can loop over layers, filter or join what several reads answer, and give back only what the task needs. The reads stay the first answer; a script is for an answer that needs several of them.

A script

  • The body of an async function, in JavaScript, not TypeScript: await works, return gives result; what console.log prints comes back as logs.
  • pw.<read>(args) is the read tool by its camelCase name, with the arguments it takes as a tool: pw.nodesFind, pw.inspect, pw.designRead, pw.tokensRead. Nothing a script calls writes.
  • types_read gives each read's whole answer type: read it before the script. Reading a key the type does not have throws pw.inspect: no field "nodes" here; fields: layers, ...; a key the type has but this answer lacks is undefined, so if (answer.more) works.
  • A number past its bound (limit over 500) runs at the bound and is listed in clamped; a key the tool does not take is refused with the keys it does.
  • A failed call throws an Error naming the function and what was wrong, e.g. pw.inspect: nodes: Invalid input: expected array; catch it to go on. A failed run still lists in calls the calls that succeeded.

Limits

  • 30 s a run by default, timeout up to 300 s; a call gets what is left of it.
  • 50 pw calls a run, 4 at once (the rest wait their turn).
  • 64 MB of memory; code that keeps the CPU busy 1 s without a pause (an endless loop) is stopped.
  • result is cut past 24,000 characters: a long list or text ends in a --- TRUNCATED --- marker, and resultChars gives the size before the cut. logs keeps the last 4,000 characters.
  • No Node, no network, no timers, no Plugin API: only pw, utils and console. Plugin code goes in code.

Images

A script cannot show an image: there is no pw.screenshot (nor pw.nodeShow or pw.selectionWait, which act on the user's view), because a client that shows only execute's structured answer drops the image blocks. Call screenshot itself for an image. pw.designRead with screenshot: true answers a handle, image: "image-1"; returned, execute sends the image after its answer, but a client may not show it.

Design XML in a script

pw.designRead answers { xml, json, tree }: the XML, its JSON block, and tree, the XML's elements as data (id, tag, attributes with the CSS and metadata such as name and textStyle, a Text's text, children), to filter layers without parsing the XML.

Utils

utils holds helpers built on pw, each of their pw calls counted in the run's limits like the script's own:

  • utils.layers(find?, { fields? }): pw.nodesFind(find), then pw.inspect of what it found, 100 ids a call, each layer's find entry with its inspect fields over it (only fields when given).
  • utils.walk(tree, visit) and utils.find(tree, test): depth first over pw.designRead's tree or utils.outlineTree(xml) of pw.outline's XML; each element comes with { path, depth, hidden }.
  • utils.map(items, fn, { limit? }): at most 4 at once, the answers in order. utils.chunk(items, size).
  • utils.color(value): a CSS colour as { r, g, b, a }, null when it is none; utils.color.same(one, other, tolerance?).

Every text of a frame with its font sizes, in a few calls rather than one per text:

const { layers } = await utils.layers({ type: "TEXT", within: "185:239" }, { fields: ["text"] });
return layers.map(({ id, text }) => ({ id, sizes: text.fontSizes }));

Every text of the frame that is shown, with its text style:

const { tree } = await pw.designRead({ node: "185:239" });
const texts = [];
utils.walk(tree, (element, { hidden }) => {
  if (element.tag === "Text" && !hidden) texts.push({ id: element.id, style: element.attributes.textStyle ?? null });
});
return texts;
