Pixelwright docs

Quick start

Requires Node.js 24.11 or newer and Figma Desktop. Run the setup in a terminal:

npx -y pixelwright@latest

It connects Claude Code and Cursor, shows what to paste for Codex and other MCP clients, and puts the Figma plugin in ~/.pixelwright/plugin. Then, in Figma Desktop:

  1. Plugins → Development → Import plugin from manifest… and pick ~/.pixelwright/plugin/manifest.json, once. Figma loads the plugin from there every time you run it, and the setup puts the new one there on every update. (The plugin is not on the Figma Community: Figma does not list plugins that overlap its own MCP server.)
  2. Open your file and run Plugins → Development → Pixelwright. Keep its small window open while you work.
  3. The first time, the window asks for a pairing code: your agent shows it (from status); type it in.
  4. Ask your agent to read a section, or turn on Allow edits in the window and ask it to change something.

npx -y pixelwright@latest setup --print asks nothing: it puts the plugin in place and prints the commands and config blocks, for scripts.

Try it on the demo

Open the Orbit demo in Figma: a small pricing site made for Pixelwright. Duplicate it to your drafts, run the plugin in your copy and follow its Start here page, which names the layer each tool shows best: three breakpoints, an A/B hero, a prototype flow, Dev Mode notes and measurements, Motion, components with an exposed instance and a slot, and the deliberate mistakes the audits find. examples/orbit is the code an agent builds from it: the tokens, the components, the Code Connect files and a baseline.

How it works

Claude Code ──stdio──► pixelwright ──ws://localhost:18720──► Pixelwright plugin ──Plugin API──► your Figma file

The plugin runs inside the file and answers the server on your computer. Every read and write goes through the Figma Plugin API, so nothing reaches api.figma.com and no seat or plan limits the number of calls. Several files can be connected at once; tools work on the one whose plugin window was in front last, or on the file you name.

Code Connect

Pixelwright runs your project's Figma Code Connect templates (*.figma.ts) and batch files (*.figma.batch.json, one row per component through a shared template), written as Figma documents them, itself, on any plan, without publishing anything. design_read then gives each connected instance as $code in the XML with its code and imports, and names the properties its code leaves out:

{ "ids": ["54:268"], "component": "PlanCard", "source": "src/components/PlanCard.tsx",
  "snippet": "<PlanCard name=\"Pro\" price=\"$12\" description=\"For freelancers shipping fast.\" popular>\n  <Button variant=\"primary\">Get started</Button>\n</PlanCard>",
  "imports": ["import { PlanCard } from \"@/components/PlanCard\"", "import { Button } from \"@/components/Button\""] }

A row or a template can name the component's key (components_read gives it), which matches exactly that component in every file, a library's included. components_read mapped=false lists the components still without code, so a design system is mapped once, a row each. See examples/orbit for two templates, one rendering the other inside it, a batch file, and how they match. The project folder is CLAUDE_PROJECT_DIR, else the folder your MCP client starts the server in.

Safety

  • Allow edits in the plugin window is off until you turn it on for a file; while it is off, the plugin refuses every write, whatever the agent asks. Your choice is remembered per file on your computer.
  • Each tool call that writes is one undo step in Figma (⌘Z / Ctrl+Z). design_apply and tokens_apply take dryRun to check a change without writing it.
  • The server listens on localhost only, and a plugin pairs once with a code you type in; unpaired windows get nothing.
  • execute runs plugin code the agent writes, and Code Connect templates run as your project's code: use Pixelwright in projects and with agents you trust, as you would their build scripts.

Limits

  • The file must be open in Figma Desktop with the plugin's window open; writing needs edit access to it.
  • Figma takes images up to 4096 px a side, in PNG, JPG or GIF.
  • A library's component the file does not use yet is placed by its key (component="key:…"): the Plugin API cannot search a library's components.
  • Tested on macOS. On Windows the setup gives Claude Code cmd /c npx …, as its documentation asks; Windows itself is not tested yet.

Commands

pixelwright                 in a terminal: the setup; started by an MCP client: the MCP server on stdio
pixelwright setup --print   no questions: the plugin put in place, the commands and config blocks printed
pixelwright serve           the MCP server, however it is started
pixelwright logs            follow the logs of every running server on this machine: tool calls, plugins, errors
pixelwright --version

PIXELWRIGHT_HOME moves ~/.pixelwright (the plugin, pairing keys, written-files.json, the shared log in logs/); CLAUDE_PROJECT_DIR names the project for Code Connect; PIXELWRIGHT_SUPPORT_REMINDERS=off turns off the weekly support note (see Support); PIXELWRIGHT_NO_UPDATE_CHECK=1 stops asking npm for a newer version (see Updating); PIXELWRIGHT_LOG_LEVEL=debug adds the bridge's details to the log.

Updating

MCP clients start pixelwright@latest, so a client started again runs the newest server. The plugin is a copy on your computer: run npx -y pixelwright@latest again (or setup --print) to put the matching one in ~/.pixelwright/plugin. Figma Desktop loads it the next time you run the plugin. When the plugin's window says the protocol versions differ, this is the fix.

When a newer version is out, the plugin's window says so at the top, with what is new in it and a link to these steps. Close it, and it stays closed until the next version. The server asks npm for the newest version once a day (the answer kept in ~/.pixelwright/latest.json); PIXELWRIGHT_NO_UPDATE_CHECK=1 turns that off, and the plugin itself never goes online.

Every MCP client session runs its own server, and they share one bridge port. When a newer server starts while an older one (another client's, still open) holds the port, the older one hands the port over and switches its bridge off: its status then asks you to restart Pixelwright in that client (/mcp in Claude Code). A plugin turned away by an older server keeps trying, and connects once the newer one holds the port.

Tools

Every tool the server lists, as your agent sees it. Tools marked writes change the file and need Allow edits.

a11y_read

What a screen's markup needs for accessibility, read from the design: its headings with levels (a text style named H2 or Heading 3 at that level, else by size, the largest h1; skipped levels and extra h1s said), its controls with their roles (link when a click goes to a screen or URL, button for other clicks, checkbox, radio, switch, tab, textbox, combobox by the component) and the label a screen reader says (an icon-only control gets an aria-label suggestion; a field's label is the text right before it), its pictures with an alt from their names, controls nested in controls, and where layers placed by hand read in another order than they show. Use it with design_read when you build the screen. contrast_check rates the texts; design_lint checks touch targets. Works while Allow edits is off.

ParameterTypeWhat it is
nodeoptionalstringThe screen or section to read. Default: the one layer selected in Figma.
fileoptionalstringThe file to work on: its session from status or its name. Default: the active file.

assets_export

The same bytes are written once, a name taken by other bytes gets -2, and a file already in dir is never overwritten with other bytes. A layer that cannot be exported is reported in errors and the rest are still written.

baseline_diff

What the designer changed since baseline_save, in design_read's terms: each layer changed (its attributes as [before, after], a text's content as XML), added (with its XML when short), removed or hidden, moved to another parent or reordered; a change made in a component once, with the instances it reached and how many were compared (of); tokens whose value changed in any mode, renamed, newly used or no longer used; icons and images drawn anew (drawing: export them again). Layers are followed by id, a replaced one by its name. It sees what changes_since and Figma's own Changed mark miss: edits made while the plugin was closed, accepted library updates, variable and style values. Without name: every baseline in the project with how much changed; call it when a session starts or the user says the design changed. It reads the file the baseline came from and works while Allow edits is off. Change only the code it names (code lists the files), then call baseline_save with the accept it gives.

ParameterTypeWhat it is
nameoptionalstringOne baseline in detail. Without it: every baseline in the project, with how much changed.
nodeoptionalstringCompare with this layer instead of the baseline's own, e.g. a v2 the designer made beside it. Needs name.
fileoptionalstringWith name: compare in this file (a session from status, or a file name). Without name: only this file's baselines. Default: the file each baseline came from.

baseline_save

Keeps a layer as you build code from it, so baseline_diff can tell later what the designer changed: its read and the values of the tokens it uses, in every mode, go into .pixelwright/baselines/<name>.json in the project (it holds the design's texts: commit the folder to share it, or leave it out of git). Save right after the design_read you build a screen or section from; name it after your code (pricing, plan-card) and list in code the files you build from it. Once your code has the changes a baseline_diff listed, pass the accept it gave: exactly the design it compared is kept, so what the designer changed after it still shows next time. An existing name is replaced only with accept or replace: true; code alone changes its file list. Writes nothing to Figma, so it works while Allow edits is off.

ParameterTypeWhat it is
nodeoptionalstringThe layer the code is built from: a frame, section, component or instance. Default: the one selected layer. Not with accept.
nameoptionalstringNamed after the code: pricing, plan-card. Default: the layer's name as a slug. Required with accept.
codeoptionalstring[]The project's files built from the layer, relative to the project. Default: the list the baseline already has.
acceptoptionalstringThe accept a baseline_diff answer gave: keeps exactly the design that diff compared.
replaceoptionalboolean
default false		Start the named baseline over from the layer as it is now. Not with accept.
fileoptionalstringThe file to work on: its session from status or its name. Default: the active file.

breakpoints_find

changes_since

What changed in the file since the plugin started watching (its window opened) or since an earlier answer's cursor: each layer created, deleted or changed (with the properties), by the user, a collaborator or Pixelwright itself, on the page the user was on. Ask with no cursor once to start, then with the cursor it gives, to read again only what the designer changed. Only pages the user had open while the plugin ran are watched; an edit made while one of Pixelwright's writes runs (or within a second after) counts as Pixelwright's, and changes from code execute left running count as the user's. What changed while the plugin was closed, and token values, baseline_diff tells against a saved baseline.

contrast_check

Rates every visible text under a layer for WCAG contrast against what is behind it (the layers below it that cover it, then its parents' fills up to the page, those above the layer named included, see-through ones laid over what is below; a see-through layer over the text, a scrim, laid over both): the ratio, whether it is large text (24 px, or 18.66 px bold), and whether it passes AA and AAA. Each run with a colour of its own has a row (a link in a sentence). A text over an image or a gradient, or over a layer that covers only part of it, is said, not guessed: check those in a screenshot; on a see-through panel (glass, its blur not weighed) the worst part under it is rated. Texts cut off by a clipping frame or hidden under an opaque layer are left out and counted. Works while Allow edits is off.

ParameterTypeWhat it is
nodeoptionalstringThe layer whose texts to check (a section, a screen). Default: the one layer selected in Figma.
fileoptionalstringThe file to work on: its session from status or its name. Default: the active file.

design_applywrites

Writes Pixelwright XML, the format design_read returns, into Figma. An element with id changes that layer: only the attributes it gives, the rest stays as it is (write background="none", width="auto" to hug, display="block" to drop auto layout); under another parent, with before/after or in another order it moves the layer. An element without id creates a layer: Frame, Section, Text, Rectangle, Ellipse, Line; a TextPath (text on a path) along d, an SVG path, or arc="cx cy r from to" in its parent, whose text and start change later but whose path does not; an Instance by component="Name" variant="Prop=Value" props="Label=Text"; a Component (prop, visibleProp and swapProp on its layers make its properties; on the layers of an existing component they bind or add them) or a ComponentSet of Component variants; an Image or Icon from a file (src); copyOf="id" copies a layer and writes the element onto the copy. var(--Name) binds the style or variable of that name; note writes Dev Mode notes; fonts are loaded for you. XML read with design_read and sent back unchanged changes nothing. Each element is written on its own: errors come back with their line and attribute while the rest goes in, and the whole call is one undo step in Figma. The plugin refuses writes while its Allow edits switch is off (dryRun checks without writing). See guide write.

default false		Check ids, tokens and fonts without writing, listing the layers it would create (without ids) and change; works with Allow edits off.

fileoptionalstringThe file to work on: its session from status or its name. Default: the active file.

design_lint

Checks layers, a page or the file against the rules a design should keep before it is built: text contrast below WCAG AA (an error), colours, texts and effects bound to no token or style, frames detached from components, stacks placed by hand that Figma reads as a flow, layers reaching past their parent's flow, grid cell or clip (a text past its column), touch targets under 24 or 44 px, interactive components without hover, focus or disabled states, raw values a token holds, spacing off the 4 px grid, instance overrides of a component's look, default layer names, hidden and empty leftovers. executewrites

Runs JavaScript in the Pixelwright plugin, for what design_apply and tokens_apply cannot say: the code is the body of an async function given figma (the Plugin API), console and pw; return gives result (layers come back as {id, type, name}, figma.mixed as "mixed"), and what it logs comes back as logs. What it throws comes back as error, with the logs before it. pw stays between calls while the plugin window is open: pw.state for your data, your own functions added to pw, and Pixelwright's helpers: await pw.node(id) (the layer, or an error), await pw.fonts(layer) (loads every font its texts use, before you change them), pw.paint(css) (a CSS colour as a solid paint), await pw.variable("--token") (the variable design_read names so). The plugin runs with documentAccess "dynamic-page": use the Async calls (getNodeByIdAsync, getMainComponentAsync, getLocalPaintStylesAsync, setFillStyleIdAsync…), and await page.loadAsync() before reading another page. figma.skipInvisibleInstanceChildren is Figma's own, false in the editor and true in Dev Mode: set to true, findAll, findOne and children skip hidden layers inside instances and getNodeByIdAsync gives null for them (it is set back after the call). Keep a long script in a file and pass its path as script: it is read at every call, so after a plugin restart or a change to the file run it again rather than calling the functions it once added to pw. What it changes during the call is one undo step in Figma, and version saves a named version first. Refused while the plugin's Allow edits switch is off, but code it starts that outlives the call (timers, listeners, work past the timeout) keeps running until the plugin window is closed, the switch notwithstanding. timeout waits up to 300 s for a long task; an endless loop, synchronous or of awaits, freezes Figma until the plugin is closed. Prefer the XML and token tools: they keep the file's styles and check what they write. To read, use the read tools (design_read, inspect, measure, nodes_find): they need no code and work with Allow edits off; a run that changed no layer on the page says so in note.

Which tool to use when, from finding a section to its files. The agent reads this with guide topic workflow.

Pixelwright reads the files open in Figma Desktop through its plugin; nothing goes through Figma's REST API. Every tool takes file (a session id from status, or a file name); without it, the active file.

  1. Connection. status lists the connected files and which one is active. None connected: the user runs the Pixelwright plugin in Figma Desktop and keeps its window open (the first time, they type the pairing code status shows into the plugin window).
  2. Find what to read.
    • file_map: every page with its frames, sections and components, in one call: where to start in a big file. devStatus says what the designer marked ready for dev (or completed): build those first, not drafts.
    • selection_get: what the user selected ("this", "the selected one"). selection_wait: ask the user to select something, then wait for it. viewport_get: what the user is looking at, when "this" comes with no selection.
    • outline: the layer tree with boxes, x and y relative to the outlined layer; node: "0:0" lists the pages. A layer with $children="N" has more children than listed: outline it on its own. An instance names its component and variant, so repeated cards show without a read; dev="ready" marks what the designer handed over for development.
    • nodes_find: layers by name, type, text, component or an instance's variant ("State=Hover, Size=L"). counts: true counts every instance found by component and variant: before deleting variants, which ones layers still use (a variant missing from the counts has no instance there).
    • node_show: brings layers into view (fitted or at a zoom) and selects them, so the user sees which you mean.
    • changes_since: what the designer changed since you last looked (a cursor), to read again only that.
  3. Read one section. design_read returns the section as XML (see guide xml), then JSON with tokens, text styles, fonts, assets, hints and truncated, plus measurements (the designer's Dev Mode measurements, in px) and motion (Figma Motion as CSS @keyframes) when the section has them. Read sections, not whole pages: past maxChars (80 000) the deepest branches are left empty with $truncated="true" and their ids listed in truncated; read each on its own. Pass assetsDir (e.g. src/assets) to get its icons and images written as files. repeats: true reads a list of alike items once ($repeat), with their data as rows: shorter, and the list's shape plain. nearby: 400 adds the designer's notes on the canvas around the screen (texts and stickies beside it, nearest first): read them, they often say what the layers cannot (states, motion, copy to change).
  4. Look at it. screenshot renders a layer to PNG (inline up to 2000 px a side, scaled down to fit; save writes a .png file full size; clip takes a region of it, in px from its box). Compare your build with it: image_compare renders a layer the same way and compares it with a PNG of your build (rmse, the share of pixels that differ, the box around them, edges off by N px; diff writes the difference as a PNG). styles_compare checks the build's computed styles (getComputedStyle) against each layer, property by property: the values that differ with the token or text style behind them, and the properties the build left out. Measure it. inspect reads layers as Figma has them, without code and with Allow edits off: the layout box and the painted box (a centred stroke, shadows and blur reach past it), the fill with the style or variables behind it (what a var() resolves to), how strokes paint, every effect's parameters (a progressive blur's start and end), a text's lines and line heights, overflow, interactions with their transitions, a component's variant, and each layer's centre. Items set around a circle (a round menu, labels on a dial): around (the circle's id, or a point) gives each centre's distance from it and its angle as CSS rotate() turns, 0 at the top, clockwise. measure gives the distances between layers, each from the one before (gaps, aligned edges, insets). Compare variants. nodes_diff says how one layer differs from another (A/B screens): the layers only one has, the attributes that differ, and icons whose drawing differs. variants_read gives a component's states as differences from its default (build :hover, :active, :disabled from them). breakpoints_find finds a screen at the page's other widths, for the media queries. flow_read maps the prototype: screens and the links between them. A screenshot in another variable mode (modes: {"Theme": "Dark"}) shows a theme without switching it in Figma.
  5. The design system. tokens_read: variables with every mode (light, dark…) and styles, as CSS, JSON or DTCG token files. tokens_usage: the layers a token is used on. components_read: the components a page uses, or the file defines, with variants and properties. design_audit: the scale a design uses (spacing, radii, font sizes, colours) and what is off it, for a file without tokens. contrast_check: every text's WCAG contrast. fonts_check: the fonts used and where the build gets each (Google Fonts links). design_lint: a layer, a page or the file checked against the general rules (contrast, raw values, detached components, overflow, touch targets, states, leftovers), each finding with its fix; tokens_bind then binds the raw values to the tokens that hold them (dryRun first, choose where several tokens hold a value). a11y_read: a screen's heading levels, control roles and labels, alts and reading order, for the markup. states_find: the hover, focus, disabled, empty, loading or error states the build will need and the design lacks.
  6. Files. assets_export: several layers, or every asset inside one, as PNG, JPG, WebP, SVG or PDF, or the images as they were placed (originals); width sizes a render by the CSS width the build shows it at (110 at scale 2: 220 px). When a file gets another name than design_read planned (planned), use the path it gives.
  7. Write. design_apply writes the same XML back into Figma: change layers by id, create new ones (see guide write, and guide layout for flex, grid and absolute placement); tokens_apply writes variables and styles in tokens_read's JSON shape (see guide tokens); effects_apply puts noise, texture or glass on layers; texts_replace changes copy across a page or the file (a dictionary at once, styles kept); instances_reattach puts detached frames back as instances, swaps components and takes overrides off; execute runs plugin code for what none of them can say. The user turns Allow edits on in the plugin window first.
  8. Code Connect. Where the project has Figma Code Connect templates (*.figma.ts) or batch files (*.figma.batch.json), design_read gives each connected instance as $code with its code in codeComponents: use that code, adding what unread names. components_read gives each component's code, and mapped: false the ones still without: map them once with a batch row each; code_connect_read checks the files (see guide code-connect).
  9. Keep the code in step with the design. Right after the design_read you build a screen or section from, baseline_save {node, name, code} keeps it in the project (.pixelwright/baselines/: commit it to share, or leave it out of git, since it holds the design's texts). When a session starts, or the user says the design changed, baseline_diff without a name says which baselines changed; with name it lists the changes in the XML's terms. Change only the code they name: a components entry whose instances cover of goes into the component's code once; export again what is marked drawing; build added layers from their xml (or design_read when it is left out). Then baseline_save {name, accept} with the accept the diff gave. Your own design_apply writes show up too: accept them once the code follows. version_save leaves the designer a named version, only when the user asks. changes_since stays the live view while the plugin is open.

Build the code from the XML with the project's own components, tokens and layout conventions: the XML is the spec, not the code to paste. Hints in design_read say what Figma left unbound (raw colours equal to tokens, raw spacing, radii and strokes Figma itself matches to a token, unnamed layers, frames without auto layout) and what instances changed outside their component's properties.

Guide: xml

The XML design_read returns: tags, metadata, CSS attributes, read-only attributes. The agent reads this with guide topic xml.

design_read writes a section as XML: one element per visible layer, Figma's layer type as the tag, CSS properties as attributes.

Tags

  • Figma's types in PascalCase: Frame, Group, Section, Component, ComponentSet, Instance, Text, Rectangle, Ellipse, Line, Slot…
  • Image: a true image (a photo, a layer filled with an image, a masked group, a layer with an effect CSS cannot draw). Its src is a PNG of what it shows.
  • Icon: a vector, or a group or instance drawn only with vector shapes (a logo). Its src is one SVG.
  • TextPath: Figma's text on a path (a label along an arc), its text written as a Text's (see Text below).
  • Span: a run inside a Text whose style differs from the text's own.
  • Hidden layers and slices are left out.

Metadata attributes, in this order

id (instance children keep I…;… ids), name (left out on a text named by its content), component and variant ("Size=Large, State=Default") on instances, props (an instance's text and boolean properties, "Label=Sign up, Icon=true"; a comma, = or backslash inside a name or value comes escaped with a backslash), description (components), note (Dev Mode annotations, "Category: text", several joined with " | "), href (a prototype link, or a text's hyperlink), mask (alpha, vector or luminance: the layer masks the layers above it), data-<collection> (a variable mode set on the layer, data-color-modes="dark"; the read's root also has the modes it takes from above), textStyle, src (assets), d and start (a text on a path).

A data-<collection>="<mode>" attribute is the selector tokens_read's CSS writes for that mode: put it on the element in the build too, and the element takes that mode's values. design_apply sets a layer's mode the same way (the collection and mode by these slugs or their own names); data-<collection>="" clears it, so the layer takes its parent's mode.

CSS attributes

Ready CSS values, in this order: display, flex-direction, flex-wrap, position, left, right, top, bottom, width, height, min/max sizes, flex, align-self, grid-row, grid-column, justify-self, padding, justify-content, align-items, align-content, gap, column-gap, row-gap, grid-template-columns/rows, transform, opacity, overflow, text-overflow, white-space, border-radius, border (or border-top…, outline), background, box-shadow, text-shadow, filter, backdrop-filter, font, letter-spacing, text-transform, text-decoration (with text-underline-offset, text-decoration-thickness), text-align, text-wrap, color.

  • Auto layout is flex (or grid); defaults are left out (row, flex-start, gap 0). A gap is written only between two or more children.
  • Sizes: fixed sizes in px; hug writes nothing; fill is flex: 1 along the parent's direction and align-self: stretch across it. The layer you read always has its width and height.
  • A child of a frame without auto layout, or an absolute child, has position: absolute and is placed against its parent element: give that parent position: relative. Constraints: right/bottom when pinned to the end, calc(50% ± n px) when centred, left and right without a width when stretched, percents when scaled.
  • A turned layer has transform: rotate() and is placed by its centre; a mirrored one scaleX(-1).
  • Colours bound to a style or variable are var(--Name), a shadow's colour too (see guide tokens); values for them are in the JSON tokens. design_apply binds only tokens the file has: tokens_apply creates new ones. In a Display P3 file every colour is color(display-p3 r g b) (as tokens_read writes it too): keep it so, it is what the designer chose. A text with a textStyle carries only what differs from the style; textStyles holds the style's font.
  • Lengths are whole pixels; letter spacing keeps fractions.

Read-only attributes (start with $)

  • $css: what the mapping cannot write back yet, as Figma's own CSS: a diamond gradient, a turned radial one, blend modes CSS has no name for, line clamps, lists, a negative gap ("children overlap").
  • $children="N": the layer has N children and not all are listed (snapshot budget or maxChars).
  • $truncated="true": the branch was emptied, or the text shortened, to fit maxChars; its id is in truncated.
  • $repeat="N": with repeats: true, the first of N alike neighbours (list items, cards, rows) stands for all of them; the JSON's repeats lists the run's layers and, a row per layer, the values they hold apart (texts, src, variant, props, href, position). Build one component and map the rows over it. Sent back, it changes only the first.
  • $code="Button": an instance the project's Code Connect template or batch row renders, written without its children; its code is in codeComponents, whose unread names the properties that code leaves out: add them (see guide code-connect). design_apply leaves its children alone.
  • $exposed="true": a nested instance its component exposes: its properties are the component's API too.
  • $visibleProp="Show subtitle", $prop="Title", $swapProp="Icon": a component's layer bound to its properties: the boolean one that shows it, the text one its characters show, the instance swap one it is. In code they are the component's props; design_apply binds and adds them with visibleProp, prop and swapProp (see guide write).
  • $css holds property: value pairs only, explained in hints: blur: progressive from 0px at 50% 0% to 8px at 50% 100% (a blur that changes across the layer; filter holds its end radius) and stroke-align: center (half of the stroke paints outside the box, which a border-box border does not; inspect gives the painted box), list-spacing: 8px (the space between a list's items, apart from paragraph spacing) and stroke-linecap: round (a line's round or square ends, which a CSS border does not draw).
  • $override="text, background": what this layer of an instance changes that its component's properties do not say (a feature text rewritten, an icon recoloured). Code built from the component cannot show it: give the component a property or a variant for it, or build that instance as a one-off. A hint lists them all.
  • $dev="ready for dev" on the read's root: the designer marked it (or a frame or section around it) ready for development (or completed).
  • $grid-style="Desktop 12": the grid style the frame's layout-grid comes from.
  • $pins="width, padding": the properties the designer pinned in the layer's Dev Mode annotations, in CSS words: take those values exactly.
  • $motion="opacity 0→1, translate-y 24→0px; 0–0.6s ease-out": the layer's Figma Motion, led by the animation style's name when one made it. The JSON's motion has it as CSS: a @keyframes per animated layer and a rule for the class it names (layers), keyframes placed over the timeline; what CSS cannot animate is a comment.
  • $on-click, $on-hover, $on-press, $on-drag, $on-mouse-enter, $on-mouse-leave, $on-mouse-down, $on-mouse-up, $on-key, $after-timeout, $on-media-hit, $on-media-end (any other trigger as $on-<trigger>): the layer's prototype interactions, e.g. $on-hover="change to Type=Hover; smart animate 300ms ease-out" (a variant to switch to on hover, and how: build it as the hover state); the easing is valid CSS, a spring drawn as linear(). A link stays href.

Text

  • &#10; is a paragraph break (Enter), &#8232; a line break inside a paragraph (Shift+Enter, <br> in HTML): never spaces.
  • line-height: normal is Figma's Auto line height, the font's own spacing (about 1.2× the size for most fonts): give it in px where the build must match; inspect shows each text's.
  • A TextPath is a text set along a path. Its characters, spans and text CSS are a Text's (it has no line height, decoration, wrapping or truncation of its own); d is the path in the layer's own box, which left and top place as for any layer, and start where the text begins on it: the path's segment (from 0) and the place along that segment (0 to 1). Guide: tokens

How tokens are named and written: styles, variables, modes, aliases, units, libraries. The agent reads this with guide topic tokens.

design_read writes a bound colour or length as var(--Name) and lists the values it used in tokens; tokens_read returns the whole set.

Names

  • A style: its name with every run of other characters than letters, digits, _ and - turned into "-": "Dark" → --Dark, "Brand/Primary 500" → --Brand-Primary-500. Letters of any script stay.
  • A variable: its Web code syntax when the designer set one (var(--surface) → --surface), else its name the same way ("space/4" → --space-4).
  • A text style is --<name>-font, holding its font shorthand: font: var(--h3-font).
  • Two styles of one kind with one name (two paint styles "Black") are different tokens: the file's first keeps --Black, the next are --Black-2, --Black-3 (tokens_read notes them with their values). Use the one the layer names. The file's own styles come first; library styles are numbered among those the page uses, so every tool means one style by a name on that page (a read from another page may number a library's Black differently). Text styles are numbered alike: the second "h1" is --h1-2-font and textStyle="h1-2", and design_apply binds it so.

tokens_read

  • It takes the file's own styles and variables, and those the current page (or within) uses from a team library: a file built on a library has its tokens there. used: false keeps only the file's own.
  • format css (default): :root holds every collection's default mode and the styles; every mode of a collection with several is a block [data-<collection>="<mode>"] with that collection's variables, the default's too (an element in it takes the default back inside another mode's). Put the attribute where design_read writes it (data-brand="dark" on a section) or on the html element for the whole page: a token in :root that points at another collection's token is computed in :root and does not follow a mode set lower in the page.
  • format json: per collection, its modes and each variable's value in every mode.
  • format dtcg: Design Tokens Format (DTCG 2025.10) files, one per mode of each collection, keyed <collection>.<mode> (the collection alone when it has one mode), and styles for the styles; aliases are {path}, a token whose path is also a group sits at the group's $root; a token takes the type of the tokens it is aliased with (a number a gap points at is a dimension). Style Dictionary and other DTCG tools read them. Named in notes: an alias to a token no file here holds (a library's, a collection left out), a name taken twice (the second suffixed -2), and what DTCG has no type for (a text variable, a boolean, an image style).
  • collections keeps only the named ones; libraries: true adds the enabled libraries' variables by name and type.
  • Past maxChars (80 000) the summary comes back, with the collections to read one at a time; with format json also the first whole variables and styles that fit.
  • An alias to a token the output leaves out (a collection you did not ask for) is named in notes.

tokens_apply

  • It takes what tokens_read returns with format json, or the same shape written by hand: collections (each with name, modes and variables: name, type if you like, values by mode name, description, token) and styles (paint, text, effect: name and value). Values are CSS, as below.
  • Collections, modes and variables are found by name in the file's own collections, or made; a new collection's first mode renames Figma's default one. A variable's type comes from its first value when not given. var(--token) makes an alias, to a variable of the call (in any order) or of the file. A token other than the name's own becomes the variable's Web code syntax.
  • A paint style's value reads as a background (colours, a colour variable), a text style's as the font shorthand with its letter spacing and case from also, as tokens_read lists them, or after it (500 12px/16px 'Inter'; letter-spacing: 0.04em; text-transform: uppercase), an effect style's as a box-shadow list with its blurs after it, or a blur alone (backdrop-filter: blur(20px), filter: blur(4px)); a shadow's colour may be a colour variable (0 4px 12px 0 var(--shadow)), as tokens_read writes a bound one. What a value leaves out, the style keeps.
  • A value a variable or style already holds is left as it is, so sending tokens_read's own output writes nothing; send only what you change. Nothing is ever deleted (use execute to remove a token).
  • A library's collection or style the file uses is never copied into the file: change it in the library.
  • More modes than the file's Figma plan allows (Starter: one a collection): that mode's error says the plan's limit and the other modes are written. A dry run cannot know the plan, and a version is saved before the write.
  • One undo step; dryRun checks names, types, modes and aliases without writing. version: "Before the brand change" first saves a named version in the file's history, for the designer to go back to, when the call changes something.

tokens_bind

  • It binds raw values to the tokens holding them exactly, as design_read writes both (#3B2FD9, 16px, a font shorthand): colour variables and paint styles, number variables (gaps, padding, radii, border widths, opacity), text styles and effect styles; a colour variable in each layer's mode, a variable only within its scopes. A colour at an opacity binds to its colour's opaque variable and keeps the opacity.
  • Results come grouped by value: bound, ambiguous (several tokens hold it: choose: [{value, token}] picks one), unmatched (no token holds it: make one with tokens_apply). A choose for a value no candidate holds snaps the layers to the token (snapped); field narrows a choice to background, border, color, gap, padding….
  • remap: [{from: "--blue-500", to: "--brand"}] moves every use of one token to another of its kind (merging duplicates); raw values are then left alone. instances: "override" rebinds the uses inside instances too, as overrides on each one: for a copy that must differ from its components, like a dark copy in a file whose plan has one mode.
  • Instances are left out: bind their main components, and the instances follow. What was put into an instance's slots is the instance's own and is bound. A slot's default content (what the component put there) is left alone, instances: "override" too: binding it would make the slot the instance's own, so later changes to the component would no longer reach it. One undo step; dryRun lists without writing, version saves a named version first when the call changes something.

Values

  • Colours as hex (rgba when see-through); a colour with an opacity variable as color-mix(in srgb, … N%, transparent) (in display-p3 in a Display P3 file).
  • Numbers in px, except opacity and font weight, which have no unit.
  • Strings quoted; booleans as true/false (CSS has no booleans); easings as CSS easing functions (a keyword, cubic-bezier(), or a spring drawn as linear()); durations in seconds.
  • An alias is var(--other). One that points nowhere is a comment and a note.

A text style is --<name>-font, with also holding --<name>-letter-spacing and --<name>-text-transform when they are not the default. A gradient paint style is a token as linear-, radial- or conic-gradient(), and tokens_apply writes one from the same CSS.

Not tokens yet

Paint styles with images, diamond gradient styles, the blurs of effect styles (tokens_apply writes them, tokens_read lists only shadows), and library variables the file does not use (Figma gives their values only once they are imported into the file: libraries: true lists them by name and type). Paint styles and effect styles that are left out are named in notes; a var() design_read writes without a value is named in its hints.

Guide: assets

What becomes a file, in which format, and how files are named. The agent reads this with guide topic assets.

Only true assets become files; everything else is CSS.

What is an asset

  • Icon (SVG): a vector, Figma Draw's text on a path or transform group, or a group, frame or instance without auto layout drawn only with vector shapes, at least one of them a true vector (a logo, an arrow in a circle). Exported with everything it draws, strokes outside its box included, and sized by that box.
  • Image (PNG at 2x): a layer filled with an image, a mask group (its bottom layer is the mask), a layer with a video, pattern or shader fill or a noise, texture or glass effect. Exported as its own box: its corners, drop shadows and outline stay CSS around it, and the rest of its look (opacity, blur, inner shadows) is left to the file, as Figma renders it.
  • A layer the designer marked for export (PNG, JPG or SVG; a PDF export is not a web asset), in that format, when it holds no text (an export on a section with text is a preview, read as layers). A frame with an image fill and children keeps its children: the image is its background, written as the original image.
  • Plain rectangles, ellipses, buttons, cards, shadows are CSS, never images.

design_read vs assets_export

  • design_read with assetsDir writes the assets of the section it reads, and its XML points at the files.
  • assets_export writes files on their own: nodes (up to 50 layers, one file each, in the format and scale you give: PNG, JPG, WebP, SVG or PDF; width, the CSS width the build shows a layer at, sets the render to width × scale px) or from (every asset inside one layer). original: true writes the images as they were placed, full size and in their own format, instead of renders.
  • design_read without assetsDir only plans names. When assets_export writes a file under another name (the name holds other bytes, the same bytes are another layer's file, an original is a JPEG), the file has planned: use its path in the src.

Files

Named after the layer (Hero photo → hero-photo.png, a component's variant added: company-logo-amazon.svg). The same bytes are written once and shared; a name already taken by other bytes gets -2; a file already in the folder is never overwritten with other bytes.

Guide: write

design_apply: changing, creating, copying and moving layers, components, instances and images with the same XML. The agent reads this with guide topic write.

design_apply takes the XML design_read returns. The user turns Allow edits on in the plugin window first; until then every call is refused (dryRun: true checks a call without writing, switch on or off). Before a write that changes many layers, pass version: "Before the hero rewrite": a named version is saved in the file's history first (not in a dry run), and the designer can go back to it; if it cannot be saved, nothing is written (version_save saves one on its own, when the user asks). In a Display P3 file, color(display-p3 …) (as design_read writes it) is written as it is, and hex, rgb() or hsl() are taken as sRGB and converted to P3.

Changing a layer

  • An element with id changes that layer, and only the attributes it gives: <Frame id="54:243" gap="48px"/> changes the gap and nothing else. Read the layer first, edit the XML, send back what you changed (sending the whole read back is fine: what the layer already has is not written again).
  • Leaving an attribute out never removes it. To remove, write the value that means none: background="none", border="none", box-shadow="none", width="auto" (hug), max-width="none", flex="none", left="auto", transform="none", display="block" (no auto layout), display="none" (hide).
  • A text: <Text id="…">New words</Text> replaces the characters and keeps the look; a <Span> (HTML's <span> too) styles a run of them. A Text without content keeps its text, so <Text id="…" color="var(--Dark)"/> only recolours it. A text inside an instance changes by its I…;… id and stays an override.
  • What Figma keeps together is completed from the layer: a new column-gap keeps its direction and wrap, a new filter keeps its shadows, a new border-bottom or padding-top keeps its other sides, a new width keeps the edge it is pinned to. A new left or right replaces both edges.
  • Moving: an element with id under another parent element moves the layer there, before="id" / after="id" puts it next to that layer, and listing layers in another order reorders them. A layer inside an instance stays where it is (only an instance's slots take new layers). An element alone (<Frame id="…"/>) moves its layer with everything inside it.
  • Each layer named is read before the write, and a call reads only so many: the layers named and the ones on the way to them come first. So a deep layer changes in one call nested as design_read writes it (screen, section, card, its text), even in a big screen; leave out the siblings that stay as they are.
  • A text design_read shortened ($truncated) is never written back: read that layer on its own to change it.
  • A hidden layer comes back with display (flex, grid or block, as it was laid out).
  • Each tag takes its own attributes: no background or gap on a Text (its colour is color), no text styles on a Frame, no auto layout on a shape; an element's id is given once (a copy has none).

Creating

  • An element without id creates a layer: Frame, Section, Text, TextPath (below), Rectangle, Ellipse, Line, Instance, Component, ComponentSet, Image, Icon, Slot. It goes inside its parent element, after the element before it (alone: last); at the top level into parent or the current page, or next to a layer with before="id" / after="id", or onto a page (below). Groups and vectors are not drawn from XML: use an Icon.
  • A page: a top-level <Page name="Screens">…</Page> makes a new page, last in the file, and creates the layers inside it there in the XML's order, each placed by its left and top (without them, beside the ones before it); a layer named by its id inside it moves onto the new page. A dry run lists the page it would make. <Page id="…"> (an id from file_map) is a page the file has: name renames it, the layers inside it are written where they are, new ones go on it. A page takes only a name, stands only at the top level, and is never deleted or reordered. Figma's Starter plan allows 3 pages: past that the error names the limit, and nothing inside that page is made.
  • A new layer has what its XML says and nothing more: no fill without background, no clipping without overflow; a new auto layout frame hugs unless sized; a new text is black unless color says otherwise.
  • A copy: <Frame copyOf="54:268" name="Card 2"> clones that layer (everything the XML cannot show comes along) and then writes the element onto the copy. Inside it, elements with the source's ids write the copy's layers, and before/after with a source's id put a layer next to the copy's: copy a card's XML, drop the root's id, add copyOf, change the title, add a new layer in the same call.

Components and instances

  • <Instance component="Heading" variant="Property 1=Green" props="Label=Our work, Has icon=false"/> makes an instance by the names design_read and components_read write: the file's components, the ones its page uses from a library, or component="key:<key>" for a library one the file does not use yet (library_search finds those keys in the libraries saved with it). variant picks the variant (values left out are the set's default), props sets its properties by their names without Figma's #id: a text, true or false for a boolean, and for an instance swap the component to show, by the name a component takes (a set's name shows its default variant) or key:<key> (props="Icon=Heart").
  • Inside a new instance, elements with another instance's ids (of the same component and variant) or the component's own write the new instance's layers, as overrides; the other instance stays as it is. <Instance copyOf="id"> copies an instance with its overrides instead.
  • An existing instance: variant switches it, props changes its properties, component swaps it to another component. A comma or = inside a name or value is escaped with a backslash, as design_read writes it. A switch or a swap gives the instance's layers new ids, so a call that switches an instance (or a copy, or one nested in a new instance) refuses edits of its layers by their old ids: switch first, read it again, then edit.
  • <Component name="Badge">…</Component> makes a component like a frame; inside it, prop="Label" on a Text makes a text property bound to it, visibleProp="Shown" a boolean property bound to the layer's visibility, and swapProp="Icon" on an Instance an instance swap property whose default is that instance's component (instances then take props="Icon=Heart"). <ComponentSet name="Badge"> holds <Component variant="Tone=Dark"> variants: they are combined into one set (the properties defined once on it) and laid out in a grid; a set given display="flex" or "grid" lays them out itself, each variant placed by its own grid-row/grid-column, align-self or flex. description describes a component or a set; an instance of a new component can follow later in the same XML.
  • An existing component takes properties the same way, so it never has to be rebuilt: prop, visibleProp and swapProp on its layers by their ids (<Instance id="54:12" swapProp="Icon"/>), or on new layers inside its <Component id="…">, bind each layer to the property of that name the component has (a variant's: its set's), or add the property once when it has none, its default the layer's value now (the text, whether it shows, the instance's component). A name a property of another kind holds is an error; a layer no component holds, or one inside an instance, is refused. properties in the answer lists what was added to existing components (a dry run's: what would be).
  • <Slot name="Content"> makes a slot in a new component; in an instance, give its <Slot id="…"> new layers.

Images, icons and notes

  • <Image src="photos/hero.jpg" width="600px" height="400px"/> makes an image from a file (PNG, JPG or GIF, up to 32 MB and 4096 px a side; convert WebP first), <Icon src="icons/arrow.svg" width="24px"/> an icon from an SVG; background="url(…)" fills any layer that takes a background with one, a new or an existing frame, rectangle or ellipse (an avatar). Paths are on the server's machine, from its folder. icons_insert finds an open-source icon (Lucide, Material Symbols, Tabler…) and inserts it at a size, in a colour or bound to a token.
  • An existing Image with another file in src takes that image, keeping its fit. A file design_read or assets_export wrote for that layer (a render of it) changes nothing wherever it went, so a read sent back keeps the originals; a picture saved over it is a new image. An existing icon is replaced by deleting it and creating a new one.
  • An Icon's width or height, new or existing, scales it whole as Figma's scale tool does: its lines and corners grow with it (a 24px icon with a 2px line at 48px has a 4px line). The drawing keeps its ratio: the width decides when both are given, else the height. The size is the one design_read writes (what the icon draws past its box included); a Frame with the same id only resizes, its lines staying as they are.
  • note="Behavior: opens the modal | Spacing: 8px" writes the layer's Dev Mode notes, the whole list, as design_read writes it (note="" removes them). Behavior: files a note under the file's annotation category of that name; a name the file has no category for stays part of the text (no category is made). | separates the layer's own notes sent back and comes before a note a category starts; elsewhere it is text, so note="Tabs: Days | Weeks" is one note (two new notes without a category take two calls). A note sent back as it was keeps its category, formatting and pinned properties; notes without text, which design_read does not show, stay.

Text on a path

  • <TextPath id="…">New words</TextPath> changes the characters of a text on a path and keeps its look, as a Text's do; its spans and text CSS (font, letter-spacing, text-transform, color, textStyle) are written as on a Text. It has no line height, underline, wrapping or truncation. start="1 0.25" moves where its text begins: the path's segment (from 0) and the place along it (0 to 1). Its path stays as Figma made it: a changed d is refused, so delete the layer and make it again. The characters go in it, never in a <Text> inside it.
  • A new one is made along d, an SVG path in its own box that left and top place (relative commands and arcs are taken, and written as Figma's lines and curves), or along arc="<cx> <cy> <r> <from> <to>", an arc of a circle in the parent: its centre and radius in px, its ends in degrees as CSS turns (0 at the top, clockwise). An arc places the layer itself, absolutely, so it takes no left or top. A to smaller than from runs back, counter-clockwise: below the centre, arc="200 200 160 225 135" runs left to right.
<Frame id="12:30" name="Round menu">
  <TextPath id="12:41" start="0 0.25">Share</TextPath>
  <TextPath name="Label" arc="200 200 160 -40 40" font="500 14px 'Inter'" color="var(--color-ink)">Settings</TextPath>
</Frame>

Values

  • Lengths in px (a bare number in a size, a place, a gap, a padding or a radius is taken as px; a bare line height is a multiple of the font size, as in CSS); var(--Name) binds the variable or style of that name, as design_read and tokens_read write them (a paint style, a colour or number variable, an effect style, on box-shadow or on a blur: backdrop-filter="var(--Blur-Backdrop)"); textStyle="h3" applies a text style. A shadow's colour can be a colour variable, inset and in text-shadow too: box-shadow="0 4px 12px 0 var(--shadow)" binds it, and design_read writes a bound one so. The variable is the shadow's whole colour, its alpha too, so it takes no color-mix(): make a variable with that alpha.
  • design_apply binds tokens and never makes them: a new variable (or paint, text or effect style) is created with tokens_apply first, then bound here by its name. A var() that names none is an error naming the near ones.
  • font is the shorthand [italic] weight size/line-height 'Family'; Figma must have the family and that weight, or the error lists the styles it has.
  • Sizes: width/height in px or auto; flex="1" fills an auto layout parent's direction, align-self="stretch" fills across it. Placement: position="absolute" with left/right/top/ bottom, calc(50% ± Npx) for the centre, percents (with the size in percents) to scale. When to use flex, grid or absolute placement, grid tracks and cells, with examples: see guide layout.
  • Gradients: background takes linear-gradient(<angle>, <stops>) (or to right…), radial-gradient(<rx> <ry> at <x> <y>, <stops>) and conic-gradient(from <angle> at <x> <y>, <stops>), a stop a colour or a token (var(--brand) 0%) and its place in percent; a text's colour and borders take colours and tokens only. Figma's diamond gradient and repeating gradients stay read-only.
  • mix-blend-mode sets how a layer blends (multiply, screen, overlay…; normal is Figma's pass through on a frame); mask="alpha" (or vector, luminance) makes a layer the mask of the layers above it in its parent, mask="none" makes it a layer again.
  • Not written yet, and refused with an error: grow weights, overflow: scroll, links on frames, dashed underlines.

Errors and undo

nodes_delete deletes layers by id (not those inside an instance: hide them with display="none"; what an instance's slot holds is its own and is deleted).

Each element is written on its own: an error names its line and attribute, and the rest of the XML still goes in. The XML may hold several top-level elements; a <Root> wrapped around them is left out. created lists the new layers' ids and names by line, changed the layers written to (inside a copy or a new instance, by their ids there); a dry run lists the same, the new layers without ids or names (and no layers inside a copy, which do not exist yet), as what it would do. One call is one undo step in Figma: the user's Cmd+Z takes the whole call back.

Effects CSS cannot write (noise, texture, glass, hidden effects) stay when a layer's box-shadow or filter changes, and a shadow sent back as it was keeps its colour variable and blend mode. effects_apply puts Figma's own noise, texture and glass on layers: a ready look (grain, film, risograph, frosted or clear glass) or its own values.

Beyond the XML: execute

execute runs JavaScript in the plugin for what design_apply and tokens_apply cannot say (removing a variable, a prototype link, a plugin data field). The code is the body of an async function given figma (the Plugin API), console and pw: await works, return gives result (Figma's layers as {id, type, name}, plain data as built), console.log lines come back as logs, and what it throws as error. What it changes during the call is one undo step, and version saves a named version in the file's history first; it needs Allow edits. The tool waits 10 s by default and up to 300 s (timeout) for a long task. Code it starts that outlives the call (timers, listeners, work past the timeout) keeps running until the plugin window is closed, Allow edits or not; an endless loop, synchronous or of awaits, freezes Figma until then. Read the result back with the read tools.

execute is for writes. Reading needs no code and no Allow edits: design_read for the XML, inspect for boxes, centres and angles around a point, measure for distances, nodes_find for instances by variant and their counts. A run that changed no layer on the page says so in note.

The plugin runs with documentAccess "dynamic-page": the synchronous lookups throw, so use the Async calls (getNodeByIdAsync, getMainComponentAsync, getLocalPaintStylesAsync, setFillStyleIdAsync…), and await page.loadAsync() before reading another page. figma.skipInvisibleInstanceChildren is Figma's own, false in the editor and true in Dev Mode: set to true, findAll, findOne and children skip hidden layers inside instances (a faster walk of a big file) and getNodeByIdAsync gives null for them; execute sets it back after the call. An error names the line and column in the code it came from.

A long script goes in a file on the server's disk, passed as script instead of code (an absolute path, or one from the server's folder): it is read at every call, so the file as it is now runs, after a plugin restart too.

pw stays from one call to the next while the plugin window is open:

  • pw.state holds your data, and functions you add to pw stay for later calls, as they were when added: after a change to their script, run the script again;
  • await pw.node(id): the layer, or an error naming the id;
  • await pw.fonts(layer): loads every font the texts in the layer use, mixed runs too, before you change their characters or sizes; it returns their names;
  • pw.paint(css): a CSS colour as a solid paint in the file's colours, its alpha as the opacity;
  • await pw.variable("--token"): the variable design_read names so, a library's imported into the file.
const card = await pw.node("54:243");
await pw.fonts(card);
for (const text of card.findAllWithCriteria({ types: ["TEXT"] })) text.textCase = "UPPER";
card.fills = [figma.variables.setBoundVariableForPaint(pw.paint("#FFF"), "color", await pw.variable("--color-surface"))];
pw.state.card = card.id;

Guide: layout

design_apply layouts: when to use flex, grid or absolute placement; grid tracks, spans and cells; pinned and centred layers. The agent reads this with guide topic layout.

design_apply lays out a frame's children as Figma does: auto layout as flex, grid auto layout as grid, or each child placed on its own (absolute). Pick the one that says what should happen when the content or the frame's size changes.

Which one

  • Flex (display="flex"): one direction. A row of buttons, a nav bar or toolbar, a list, a stack of sections, a card's content. Children follow each other; one can take the room left.
  • Grid (display="grid"): two directions, items lined up in rows and columns at once. Card grids, bento boxes, galleries, forms with a label column and a field column, pricing tables, footers with link columns.
  • Absolute (position="absolute" with left, right, top, bottom): a layer over the others or pinned to a corner or an edge. A badge, a close button, an overlay, a decorative shape, layered images in a hero. Never for content that should reflow: it stays where it is pinned when the text or the cards around it grow.
  • Nest them: a grid of cards, each card a flex column with an absolute badge.

Flex

  • display="flex" is a row, flex-direction="column" a column (no reverse order); flex-wrap="wrap" wraps either. gap spaces the children and the wrapped lines; row-gap and column-gap set one axis each, as in CSS.
  • padding takes 1 to 4 lengths. justify-content aligns along the direction (flex-start, center, flex-end, space-between, space-around, space-evenly; a spread ignores gap), align-items across it (flex-start, center, flex-end, baseline). Figma aligns all children alike: a child's align-self takes only stretch or auto.
  • A child's size: width/height in px is fixed; none (or auto) hugs its content; flex="1" takes the room left along the direction (Figma has no other weights); align-self="stretch" fills across it; min-width, max-width, min-height and max-height set limits. A new frame with display hugs what it holds unless sized or filling.

Grid

  • display="grid" with grid-template-columns and grid-template-rows, each a list of tracks: 200px is fixed, 1fr takes a share of the room left (2fr twice as much), auto fits its content; repeat(3, 1fr) repeats one track.
  • Give both lists: a new grid has 2 columns and 2 rows, and an empty row still takes room. fr tracks share the grid's own size: give the grid a width (a height for fr rows) or let it fill its parent; on an axis where the grid hugs, Figma turns fr into auto.
  • gap="16px" spaces rows and columns alike, gap="12px 24px" rows then columns; row-gap and column-gap set one each (design_read writes these two). padding works as in flex. justify-content and align-items are refused on a grid: align each child in its cell.
  • Place a child with grid-column and grid-row, lines counted from 1 as in CSS: grid-column="3" is the third column, grid-column="1 / span 2" (or "1 / 3") two columns from the first, grid-row="2 / span 3" three rows from the second. Always give the start line.
  • A child without them takes the next free cell, row by row in the XML's order, and a cell holds one child: place every child of a grid, or none. A child with no free cell left goes into a new row at the end, sized like the last one (columns are never added). A cell past the tracks, a span past the last track or a taken cell is refused with Figma's error, and the child stays in the next free cell.
  • In its cell a child keeps its size and sits in the top left corner, or where justify-self (horizontally) and align-self (vertically) put it: start, center, end, or stretch to fill the cell's width or height instead of a size of its own. flex="1" does not fill a cell.
  • Move or delete the children of a row or column before taking it out of the tracks.
  • design_read writes a grid the same way: three or more equal tracks as repeat(), the grid's padding, each child's grid-row and grid-column from 1, span when it spans, and stretch for a child that fills its cell.

Absolute

  • position="absolute" takes a layer out of its flex or grid parent's flow: the other children, the padding and the gap act as if it were not there. It is placed against its parent and moves with it, so nest it in the frame it belongs to (the card, not the grid around the cards). Later in the XML is drawn on top (there is no z-index). position="relative" puts it back in the flow.
  • Every child of a frame without auto layout (no display, or display="block"), of a section and of the page is placed so, by its edges (design_read writes position="absolute" there; nothing flows, so it may be left out). Without edges it lands in the top left corner. left or top on a layer that flows in auto layout without position="absolute" is refused.
  • Edges in px: left/top pin it to the start; right/bottom to the end, where it stays when the parent is resized (right="12px" top="12px" is a top right badge; right="-8px" top="-8px" hangs it over the corner of a parent that does not clip); left and right stretch it with the parent (top and bottom likewise), between them without a width; a width given too wins over right, as in CSS, and it still stretches.
  • Centred: left="calc(50% - 24px)" puts the left edge 24 px left of the centre, which centres a layer 48 px wide (half its size; top likewise), and keeps it there when the parent is resized; left="50%" puts the edge on the centre. Scaled with the parent: left="5%" with width="25%" (top with height). Only left and top take calc() and percents; tokens cannot place a layer.
  • On the page itself a layer is placed by left and top alone (<Section id="…" top="800px"/> moves a section down); without them a new one goes beside the page's layers.

Not supported

  • Grid: minmax(), fit-content(), auto-fill and auto-fit, repeat() of several tracks, named lines and areas (grid-template-areas, grid-area), span without a start line, negative lines, grid-auto-flow, grid-auto-rows, justify-items and aligning the whole grid, subgrids.
  • Flex: reverse directions, grow weights other than 1, flex-basis, order (the XML's order is the order).
  • Absolute: z-index, inset, position: fixed and sticky, calc() other than around 50%, percents or calc() on right and bottom.

Guide: code-connect

Figma Code Connect: templates and batch files, keys, how design_read runs them, what the code leaves out, mapping a design system. The agent reads this with guide topic code-connect.

Pixelwright runs the project's Figma Code Connect files itself, on any Figma plan, without a token and without publishing anything: design_read gives each instance a connection builds as $code in the XML (no children) and its code in codeComponents ({ ids, component, template, source, snippet, imports, unread }: instances with the same code once), with the read's imports once each and the failures in codeErrors ({ template, error, ids }). Nested connected instances are inside their parent's snippet; the layer the read is of is never collapsed. The code takes at most 40% of maxChars (the XML the rest), and all templates of a read five seconds: past either, instances are read as layers. code: false reads every instance as layers.

Mapping a design system

  1. design_read the section; its hints name the components shown without code.
  2. components_read within=<id> mapped=false gives each one's key, properties, variants and exposed instances.
  3. Find the code component that builds it in the project (search the code; links: true reads the links people attached in Dev Mode, on paid plans, with the project file a code link points at).
  4. Confirm each pair with the user.
  5. Write a batch row (below), or a template for a component that needs logic of its own.
  6. code_connect_read checks it: by, unread, values, missing and the problems.
  7. design_read again: the instances are $code now.

Batch files: one row per component

A *.figma.batch.json file (Figma's own format) holds one group { "templateFile", "components" }, or an array of them; each row runs through the group's shared template (ending .figma.batch.ts or .js, next to the batch file), which reads the row as figma.batch:

{
  "templateFile": "./component.figma.batch.ts",
  "components": [
    { "key": "2f31fdc95b9804804df14c93a7f9c8913d611c17", "component": "PricingTier",
      "source": "src/components/PricingTier.tsx",
      "imports": ["import { PricingTier } from \"@/components/PricingTier\""],
      "props": { "Name": "name", "Price": "price", "Popular": "popular",
                 "Tier": { "prop": "tier", "values": { "Pro": "pro", "Free": "free" } },
                 "Description": "children" } }
  ]
}

The shared template (examples/orbit/components/component.figma.batch.ts) writes the row's component with each props entry: "Name": "name" passes the value, { "prop", "values" } maps a variant's (getEnum) or a toggle's (getBoolean) value, a prop named children goes between the tags, true is a bare prop, false, null and "" write nothing; imports are the row's, the id its id else the component. For Vue, use the same template with figma.code in place of figma.tsx: a Vue template takes the same tags, string props and bare toggles. A row is named <batch file>#<n>, n counting from 1 across the file's groups.

Keys and matching

components_read gives each component's key, the same in every file, a library's included. A row's "key" or a template's // key= (Pixelwright's addition, which Figma's CLI skips) connects exactly that component or set: a keyed connection matches by key only. Figma's CLI needs a url (// url=) to publish a file; Pixelwright does not, and says so once per file. Without a key, a connection matches by the id its url names (a component this file defines) with the names agreeing, then by name (the Figma name's last part against component, else the file name before .figma., case, spaces and punctuation aside: Buttons/Primary Button matches PrimaryButton), then by the id alone. code_connect_read gives the rule each matched by as by (key, id, name). A component made again, or copied, gets a new key: its keyed connection then misses, and the component shows as unconnected.

What the code leaves out

  • unread names the properties no code read: the instance's own (Description), and those of the nested instances it exposes or whose properties it overrides (Button.Label). A text whose value the snippet holds counts as read. Write them in, or read the instance with node=<id>: the values are on the element (variant, props).
  • values (code_connect_read) names the variant values a getEnum mapping misses: Figma renders them as undefined.
  • missing marks a source that names a file in neither the project nor beside the Code Connect file (packages and URLs are not checked).
  • exposed (components_read) and $exposed (design_read) mark the nested instances a component exposes: their properties are the component's API too, so in code they are its props.

Where the files are

The project folder is CLAUDE_PROJECT_DIR, else the server's working directory (never the home folder or the disk's root). Code Connect files are those ending in .figma.ts, .figma.js, .figma.template.ts, .figma.template.js or .figma.batch.json among those figma.config.json's codeConnect.include globs name (minus exclude; its documentUrlSubstitutions are applied to urls), else all such files; dependency and build folders are never searched. A batch file a custom include misses is left out, as Figma does, and named in the problems.

export default {
  example: figma.tsx`<Button size="${size}"${figma.helpers.react.renderProp('disabled', button.getBoolean('Disabled'))}>${button.getString('Label')}${icon?.executeTemplate().example}</Button>`,
  imports: ['import { Button } from "@/components/Button"'],
  id: 'button',
}
  • url: the component's or component set's link (Copy link in Figma), or key (above). component: the code component's name, as Figma's Code Connect defines it ($code shows it). source: the code component's file.
  • Imports: figma and the template's own relative helpers (import { sizes } from './helpers', TypeScript or JavaScript); nothing else.
  • The API: figma.selectedInstance (alias currentLayer) with getString, getBoolean(name, mapping?), getEnum, getPropertyValue, getInstanceSwap, getSlot (the slot layer named after the property, connectedInstances), findInstance, findText, findLayers, findConnectedInstance(s) (with path and traverseInstances), executeTemplate, hasCodeConnect, codeConnectId, id, properties; figma.code, tsx, html, swift, kotlin, figma.helpers.react.*, figma.properties.*. Property names are as Figma shows them (without the #id suffix). Hidden layers are not found.
  • Errors are the instance's alone: PROPERTY_NOT_FOUND, CHILD_LAYER_NOT_FOUND (when the missing layer is rendered), TEMPLATE_TIMEOUT (one second per instance, nested templates included; the template is not run again in that read), TEMPLATE_BUDGET, TEMPLATE_IMPORT, TEMPLATE_CYCLE, TEMPLATE_CUT (the read left out layers the code needs: read the instance on its own). Such an instance is read as usual, with its children.
  • Old figma.connect(...) files are not run: npx figma connect migrate turns them into templates.

Templates run on this computer as the project's own code, in a separate context without require, process or files, but that context is no protection against a hostile template: run Pixelwright only in projects you trust, as you would their build scripts.

Guide: email

Turning the XML into an HTML email that renders in Gmail, Outlook and Apple Mail. The agent reads this with guide topic email.

Email clients are not browsers: Gmail strips <style> blocks it does not like, Outlook on Windows renders with Word and ignores flex, grid, position and most of CSS. Read the section with design_read (and screenshot to compare), then translate:

Layout

  • The design's width (usually 600 px) becomes a centred <table width="600"> inside a 100%-wide wrapper table.
  • Every flex column is a stack of table rows; every flex row is one row with a <td> per child; gap becomes padding on the cells or spacer cells; justify-content/align-items become align and valign on cells.
  • position: absolute has no email equivalent: text over a picture means a background image on the cell (with a solid background colour as the fallback) or one image with the text in it and alt.
  • Write sizes as attributes too (width, height on tables, cells and images), not only in CSS.

Styles

  • Inline every style on its element (style="…"); keep a small <style> only for media queries and dark mode.
  • Colours from tokens as plain hex: email clients do not support var().
  • Fonts: the fonts list tells which families the design uses. Web fonts load in Apple Mail and some others only: always end the stack with a safe fallback ('Satoshi', Arial, sans-serif).
  • Borders, radius, padding and background colours work on cells; box-shadow, filter and backdrop-filter do not render in most clients: drop them or bake them into an image.

Images

  • Export with assetsDir or assets_export at 2x (the default) and give each <img> its 1x width and height attributes, display:block, border:0 and a real alt.
  • Icons as SVG do not render in many clients: export them as PNG (assets_export with format: "PNG").
  • Host the files on a server or CDN; email clients cannot read local paths.

Links and text

  • Every button is a link (href in the XML when the design has one): a table cell with the background colour and an <a> with padding inside, never a <button>.
  • Keep the text as text, not images, so it can be read and translated; give line heights in px.

Dark mode

Clients invert colours on their own; check the result with a screenshot of the light design, and add @media (prefers-color-scheme: dark) rules (supported in Apple Mail and Outlook for Mac) for logos and backgrounds that turn unreadable.
